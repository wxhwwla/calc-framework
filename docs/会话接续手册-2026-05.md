### 4.25 能力值加成：平值/百分比两阶段 + normal_skills 直读（2026-05-26，进行中）

**背景**：武器数据中技能存储在 `normal_skills` / `special_skills` 列表，旧计算逻辑只从武器顶层 dict key 直接读（如 `weapon["主能力+"]`），导致所有武器加成全被遗漏。同时 `主能力+`/`副能力+`/`全能力+` 是**百分比加成**，而非平值。

**新的正确计算模型**：

```
主能力_平值 = 角色基础 + 主能力值+ + {main_attr}+ + 装备 + 信赖
主能力_最终 = 主能力_平值 × (1 + 主能力+%/100 + 全能力+%/100)

副能力_平值 = 角色基础 + 副能力值+ + {sub_attr}+ + 装备
副能力_最终 = 副能力_平值 × (1 + 副能力+%/100 + 全能力+%/100)

能力值加成 = 主能力_最终 × 0.005 + 副能力_最终 × 0.002
```

1. [`zone_snapshot/types.py:L72`](../calc_engine/endfield/calc/zone_snapshot/types.py#L72) — `WeaponBonusSelection.calculation_kwargs()` 返回 `dict[str, int | str]`
2. [`dag_adapter/adapter.py:L97`](../calc_engine/endfield/calc/dag_adapter/adapter.py#L97) — `kwargs = selection.bonuses.calculation_kwargs()` → 变量推断为 `dict[str, int | str]`
3. `**kwargs` 拆包 → 每个 keyword 值是 `int | str` → 对 `int` 形参和 `str` 形参同时报错

**修复**：在两个调用点标注变量为 `dict[str, Any]`（拆包语义上确实没有 per-key 粒度）：

| 文件 | 行 | 修复 |
|------|-----|------|
| `calc_engine/.../dag_adapter/adapter.py` | 97 | `kwargs: dict[str, Any] = ...` |
| `calc_engine/.../zone_snapshot/compute.py` | — | `kwargs` 在 `types.py` 的 `calculation_kwargs()` 方法中定义 |

**效果**：消除 148 个级联类型错误（包端 538→390）。

**原则**：当 `**kwargs` 拆包时，变量应标注为 `dict[str, Any]` 以抹平联合值类型。这不是偷懒——是类型系统在 `**` 语法的真实能力边界。

**文档更新**：[`docs/代码规范-ruff修复模式.md`](代码规范-ruff修复模式.md) §7.2 新增 `**kwargs` 拆包 + 联合值类型条目。

**勿重复做**：在返回 `dict[str, T1 | T2]` 的函数返回类型上加 `Any`（正确做法是在调用点宽化）；将 `**kwargs` 替换为具名关键字传递（破坏兼容性）。

**Learnings**：

| 限制 | 说明 | 规避 |
|------|------|------|

### 4.96 PythonAnywhere 自动化部署脚本（2026-05-31，已完成）

**背景**：之前手工部署到 PythonAnywhere 的流程需要 6+ 步骤（构建、`Compress-Archive`、Files 上传、Bash 中逐一执行 git pull / pip / unzip、Web 页面 Reload），且多次踩坑（LZMA 不兼容、dist/dist/ 嵌套、Bash 多行粘贴卡死、忘记 Reload）。

**新增文件**：

| 文件 | 说明 |
|------|------|
| `web/scripts/deploy_pythonanywhere.py` | 本地部署脚本：npm run build → zipfile 打包 → 可选 API 上传 + 自动 Reload |
| `web/scripts/deploy_server.sh` | 服务器端脚本：git pull → pip install → 解压 dist → 清理 |

**关键设计**：

| 设计决策 | 理由 |
|----------|------|
| Python `zipfile.ZIP_DEFLATED` 代替 `Compress-Archive` | `Compress-Archive` 默认 LZMA，Linux `unzip` 不兼容 |
| zip 以 dist/ 内容为根（非 dist/ 本身） | 避免 `dist/dist/index.html` 双层嵌套 |
| 服务器脚本自动检测/修复嵌套 | `if [ -d dist ]; then cp -r dist/* .; rm -rf dist; fi` |
| API Token 可选 | 免费套餐可用；未配置时脚本输出手动操作指南 |
| `~/.pythonanywhere` 配置文件 | 避免每次键入参数；环境变量可覆盖 |
| `--all` 一键全自动 | 构建 → zip → 上传 → 部署脚本 → Reload，5 步一条命令 |

**使用方式**：`python web/scripts/deploy_pythonanywhere.py --help`

| 选项 | 作用 |
|------|------|
| 无参数 | 构建 + 打包，输出 zip 和手动操作指南 |
| `--upload` | 构建 + 打包 + 上传到服务器 |
| `--reload` | 自动触发 PythonAnywhere Web App Reload |
| `--all` | 全自动：构建 + 打包 + 上传 + 部署脚本 + Reload |
| `--zip-only` | 仅重新打包已有 dist/（跳过 npm 构建） |
| `--init-config` | 生成 `~/.pythonanywhere` 配置模板 |

**服务器端脚本**：`bash web/scripts/deploy_server.sh`
- 支持 `--no-pull`（跳过 git pull）、`--no-pip`（跳过 pip）、`--zip=路径`
- 自动查找 `~/dist.zip`、`frontend/dist.zip` 等常见路径
- 解压后自动检测并修复 `dist/dist/` 嵌套

**验证结果**：`python -c "import ast; ast.parse(...)"` — 语法正确。
