## 1. 结论与风险总览

项目已有可运行计算核心、桌面/Web 两端、较完整的测试与 CI、ADR、许可说明、构建脚本和本地验收记录，不是“只有文档没有实现”的空壳项目。

但当前仍不能据此认定“代码与文档可以互相证明，并可被独立的人复现、维护和交付”，主要原因是：

1. **存在高危本地文件安全边界缺口**：打开 `.calcpack` 时的资源解压没有阻止路径穿越，也没有压缩包资源上限。
2. **部分公开承诺强于实现**：AI“最优配装”并未执行最优搜索；当前 Release 没有文档所述安装器和当前源码制品。
3. **全绿 CI 仍有盲区**：有测试接受 HTTP 500、把计算异常转为 skip，原生 Qt 崩溃可被容错为成功。
4. **发布与运维闭环不完整**：PyPI 发布标签可能与实际 wheel 源码版本不一致；自动更新只替换 exe；Docker 没有运行数据持久化和备份恢复方案。
5. **活跃文档存在系统性漂移**：更新日志、版本、依赖、架构、API 数量和玩家命令均有过期或互相冲突内容。

## 3. P0：安全边界

### R-01 打开 `.calcpack` 可发生资源路径穿越，且压缩包读取无资源上限

- **风险等级**：P0。
- **状态**：已修复（2026-11-06，第一批）。条目名 / 数量 / 总大小 / 符号链接均在解压前校验，写入前 `resolve()` + `is_relative_to()`；测试覆盖 `../`、绝对路径、盘符、反斜杠、同前缀兄弟目录与 ZIP bomb。正常包流程由现有测试覆盖。
- **证据**：
  - `framework/src/calc_framework/ui/viewer_pack_utils.py:59-72` 遍历 ZIP 全部条目并用 `zf.read(name)` 一次性读入，没有条目数、单文件或总解压大小限制。
  - `framework/src/calc_framework/ui/viewer_pack_utils.py:200-215` 对任何以 `assets/` 开头的条目直接执行 `dest = target / name`、创建父目录并写入，没有拒绝绝对路径、`..` 或校验 `dest.resolve().is_relative_to(target)`。
  - `framework/src/calc_framework/ui/viewer_render.py:80-95` 的普通 `load_calcpack()` 流程会自动调用上述资源提取函数。
  - `framework/src/calc_framework/ui/viewer_help_content.py:25-30`、`:76-80` 明确引导用户打开或拖入 `.calcpack`，因此这不是不可达的内部函数。
- **影响**：恶意 `assets/../../...` 条目可在当前用户权限下写到资源临时目录之外；高压缩比或超大条目还可能导致内存/磁盘耗尽。
- **修复建议**：
  1. 对每个 ZIP 条目使用规范化相对路径，拒绝绝对路径、盘符、反斜杠绕路和任何 `..` 分量；写入前用 `resolve()` + `is_relative_to()` 做最终边界校验。
  2. 只允许预期资源扩展名和明确子目录；不要仅检查字符串 `startswith("assets/")`。
  3. 在读取前限制条目数、单条目解压大小、总解压大小和压缩比；资源提取采用流式复制并执行同样的限额。
  4. 复用或抽取 `tools/calc_mcp/package.py:174-201` 已有的安全解压思路，避免不同入口各自实现。
- **验收标准**：路径穿越、绝对路径、混合分隔符、符号链接、ZIP bomb、超限条目均被拒绝；目标目录外没有任何文件变化；正常 `.calcpack` 的桌面与 Web 流程保持可用。

### R-02 “AI 最优配装”没有执行最优搜索，返回的是硬编码基线

- **风险等级**：P1。
- **状态**：静态确认。
- **证据**：

  - `web/backend/api/ai.py:138-193` 没有调用搜索引擎；只以硬编码角色属性和敌人参数做一次 DAG 基线求值，并把它放入 `top_results`。
  - `web/frontend/src/components/calculator/AiRecommendDialog.tsx:107-123` 将该结果显示为“搜索空间”和推荐结果。
- **影响**：用户会把与当前配装无关的基线误认为最优推荐；这是功能承诺与实现不一致，不只是文案精度问题。

### R-03 AI 出站 HTTPS 的 IP 替换没有保留 TLS SNI/证书主机名

- **风险等级**：P1。
- **状态**：静态确认协议风险；未调用真实 AI 服务。
- **证据**：
  - `web/backend/api/internal/safe_http.py:144-154` 将目标 URL 主机名替换为 DNS 解析 IP，仅额外设置 HTTP `Host` 头。
  - 对 `https://api.openai.com/v1` 等正常服务，TLS 客户端仍会以 URL 中的 IP 做 SNI/证书主机名校验；HTTP `Host` 不能代替 TLS 身份验证。
  - `web/backend/tests/test_security_fixes.py:78-89` 只验证 URL 字符串重建和 IP 保存，没有覆盖真实 TLS 握手。
- **影响**：标准 OpenAI/DeepSeek 等 HTTPS 服务可能因证书名称不匹配而无法使用；若为绕过问题关闭证书校验，会引入更大安全风险。
- **修复建议**：使用支持“连接固定 IP、TLS 仍使用原域名”的传输实现，同时保留现有私网拒绝；不要通过 `verify=False` 修复。若无法可靠实现，应重新评估 DNS 固定方案。
- **验收标准**：使用仅对测试域名签发证书的本机 HTTPS 服务证明握手成功且连接到固定 IP；错误证书、私网地址和 DNS 重绑定仍被拒绝；至少一个真实兼容服务的冒烟记录可追溯。
