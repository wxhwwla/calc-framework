## 1. 长远目标

将项目打造为一套**完整的抽象框架**，可以接入任何以数值驱动的游戏，实现「一套框架，万物可算」。

### 1.1 核心理念

框架按三层设计流程构建：

```
第一层：乘区层（计算引擎）
  ├── DAG 图编辑器 — 可视化编辑所有乘区所需的计算逻辑
  ├── 复合节点封装 — 将细粒度 DAG 节点组合为可复用的复合节点
  ├── 封装为块（Block） — 复合节点进一步封装为逻辑块（如属性块、攻击力块）
  ├── 遍历逻辑 — 配装搜索/枚举框架
  └── 数据接入 — 编辑器读取已有数据（爬虫/手动录入/OCR 等），辅助验证乘区是否正确

第二层：布局层（UI 设计器）
  ├── 可视化布局编辑器 — 类似 Qt 的拖拽式控件放置（选项框、下拉框等）
  ├── 乘区映射 — 将第一层的乘区变量映射到 UI 控件中
  └── 布局导出 — 输出一个布局定义文件

第三层：展示层（用户框架）
  ├── 加载布局文件 + 数据文件
  └── 供终端用户直接使用的计算界面
```

### 1.2 目标形态

| 维度 | 目标 |
|------|------|
| 受众 | C 端全体玩家 + B 端游戏从业者（数值策划、独立开发者、攻略作者） |
| 品类 | 端游/手游/单机/网游/MOBA/FPS/回合制/战棋 — 任意数值驱动游戏 |
| 内核 | 纯数学引擎 + 动态规则配置，与具体游戏解耦 |
| 扩展 | 数据接入（爬虫/手动/OCR 等多来源）、插件工坊（Calc Hub）、社区共享配置 |
| 商业模式 | GPL 开源内核 + 商业双授权（可选） |

## 3. 数据与编辑器设计理念

### 3.1 数据结构定位

已有 `tools/bwiki_scout/` 爬虫爬取了终末地的角色/武器/装备 JSON 数据。这些数据经过 `tools/data_pipeline/` 的 ETL 清洗后，形成标准四层 schema（EntitySchema / SkillSchema / SegmentSchema）。

**这些标准格式的数据就是模板**：
- 后续任何游戏的清洗流程都按这套结构来
- 开发者工具（`tools/designer/`）直接读取这些数据
- 用户可以在数据编辑器中看到已有数据，并验证乘区计算是否与游戏数据吻合

### 3.2 数据接入方式（并列可选，非必须）

| 方式 | 状态 | 说明 |
|------|------|------|
| **爬虫/脚本**（BWIKI scout） | ✅ 已有 | `tools/bwiki_scout/` 已爬取终末地全量数据 |
| **手动录入** | ✅ 已有 | `tools/data_pipeline/` CSV/JSON → 标准 schema |
| **手动 JSON 编辑** | ✅ 已有 | 直接编辑 `characters.json` / `weapons.json` |
| **OCR 截图识别** | ✅ 已完成 | `tools/ocr/` 完整管线（TorchVision 检测 + EasyOCR 识别 + OcrMapper 映射 → 一键填入计算器） |

OCR **不是必须的** — 它只是数据接入的选项之一，与爬虫、手动录入并列。

#### P4：Web 版框架 — 三 GUI 同步 Web 化

P4 将三个 PySide6 GUI 完整移植到 Web 端（React + FastAPI），并建立「一套声明 - 两端渲染」的同步机制，避免两份代码各自演化。

##### P4 核心理念：声明式同步

```
                  ┌──────────────────────────────┐
                  │     Shared Declarations       │
                  │  layout.json / attr_schema    │
                  │  DAG files / data JSON        │
                  │  (in adapter/ 和 data/ 目录)   │
                  └──────┬───────────────┬───────┘
                         │               │
              ┌──────────▼────┐   ┌──────▼───────────┐
              │ PySide6 GUI   │   │ FastAPI Backend   │
              │ (existing)    │   │ (web/backend/)    │
              │ ComputeSheet  │   │ /api/* 数据接口    │
              └───────────────┘   └──────┬───────────┘
                                         │
                               ┌─────────▼──────────┐
                               │ React Web Frontend │
                               │ (web/frontend/)    │
                               │ Web ComputeSheet   │
                               │ 渲染同一份 layout   │
                               └────────────────────┘
```

**同步维度**：

| 层 | 可共享？ | 机制 |
|----|---------|------|
| `layout.json` / `attr_schema.json` | ✅ 完全共享 | 同一份文件，PySide6 和 React 各自渲染 |
| `adapters/endfield/calc/` 计算引擎 | ✅ 完全共享 | PySide6 直接调用；Web 通过 FastAPI `/api/compute/evaluate` 调用 |
| `data/` (characters/weapons/equipments) | ✅ 完全共享 | PySide6 直接读 JSON；Web 通过 FastAPI `/api/data/*` 获取 |
| `controls.py` `infer_control()` | ✅ 逻辑可共享 | TypeScript 等价实现，或 Web 端调 API 获取控件推断 |
| PySide6 ComputeSheet (QWidget) | ❌ 需重写 | React 版 `WebComputeSheet` 组件，消费同一 `layout.json` |
| PySide6 QtApp / 选择面板 / 设计器 | ❌ 需重写 | React 端各自实现等价 UI |
| DAG 图编辑 (QGraphicsView) | ❌ 需重写 | React Flow 已有初步集成 |
