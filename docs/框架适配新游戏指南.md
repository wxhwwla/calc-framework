# 框架适配新游戏 — 从零到完整计算器

本文档指导开发者使用 calc-framework 为一款新游戏创建完整的数值计算适配包。
读完本文你将能：创建 DAG 公式 → 设计 UI 布局 → 打包为 `.calcpack` → 用 CalcPackViewer 加载运行。

---

## 一、框架全景

```
┌──────────────────────────────────────────────────────────────┐
│                    calc-framework (核心引擎)                   │
│  DAG 求值引擎  ·  搜索枚举引擎  ·  插件注册表  ·  主题管理器    │
│  ComputeSheet  ·  CalcPackViewer  ·  布局/图编辑器            │
└────────────────────┬─────────────────────────────────────────┘
                     │  adapter discover (自动发现)
     ┌───────────────┼───────────────┬──────────────┐
     ▼               ▼               ▼              ▼
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ endfield │  │ arknights │  │ card_rpg │  │ 你的游戏  │  ← 你在这里
│ 终末地    │  │ 明日方舟   │  │ 验证用    │  │ 适配包    │
└──────────┘  └──────────┘  └──────────┘  └──────────┘
```

每个适配包是一个独立目录，放在 `framework/adapters/` 下，框架启动时自动发现。已有真实适配器包括 **endfield**（终末地）和 **arknights**（明日方舟），以及验证用的 **card_rpg**、**moba** 等。
一个适配包 = **公式定义** + **变量描述** + **UI 布局** + **自定义函数** + **可选数据文件**。

---

## 二、创建适配包 — 最小步骤

### 2.1 目录结构

在 `framework/adapters/` 下创建你的游戏目录：

```
framework/adapters/your_game/
├── meta.json              # 适配包元信息（必需）
├── your_game.dag.json     # DAG 公式定义（必需）
├── attr_schema.json       # 变量属性描述（推荐）
├── functions.py           # 自定义纯函数（可选）
├── ui/
│   └── layout.json        # UI 布局定义（推荐）
└── data/                  # 游戏数据文件（可选）
    ├── characters.json
    ├── weapons.json
    └── ...
```

### 2.2 meta.json — 适配包身份证

```json
{
  "name": "你的游戏名称",
  "game": "你的游戏",
  "version": "1.0.0",
  "schema_version": "dag-v1",
  "entry_dag": "your_game.dag.json",
  "description": "简短描述",
  "author": "你的名字",
  "tags": ["rpg", "strategy"],
  "attr_schema": "attr_schema.json",
  "functions": {
    "clamp": "functions.py",
    "lerp": "functions.py"
  }
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 适配包显示名 |
| `entry_dag` | ✅ | 入口 DAG 文件名 |
| `schema_version` | ✅ | 固定 `dag-v1` |
| `attr_schema` | ❌ | 变量属性描述文件路径 |
| `functions` | ❌ | 自定义函数注册表 |
| `entity_selectors` | ❌ | 查看器级联选择器配置（见 §2.6.1） |
| `entity_detail` | ❌ | 查看器最左列实体字段明细（见 §2.6.2） |
| `entity_input_rules` | ❌ | 按实体字段灰显无关输入（见 §2.6.3） |

### 2.3 DAG 公式 — 定义数值计算

DAG（有向无环图）是框架的核心。你定义节点和连线，引擎自动拓扑排序求值。

**示例：攻击力公式**

```json
{
  "schema_version": "dag-v1",
  "name": "攻击力计算链",
  "description": "最终攻击力 = (角色基础 + 武器基础) × (1 + 攻击力%) + 附加攻击",
  "variables": {
    "character.base_atk": {
      "type": "float", "source": "character",
      "default": 100, "description": "角色基础攻击力"
    },
    "weapon.base_atk": {
      "type": "float", "source": "weapon",
      "default": 50, "description": "武器基础攻击力"
    },
    "weapon.atk_pct": {
      "type": "float", "source": "weapon",
      "default": 0.15, "description": "攻击力%加成"
    },
    "weapon.flat_atk": {
      "type": "float", "source": "weapon",
      "default": 10, "description": "附加攻击力"
    }
  },
  "nodes": {
    "char_val":    { "type": "var",  "path": "character.base_atk" },
    "weapon_val":  { "type": "var",  "path": "weapon.base_atk" },
    "atk_pct":     { "type": "var",  "path": "weapon.atk_pct" },
    "flat_val":    { "type": "var",  "path": "weapon.flat_atk" },
    "const_1":     { "type": "const", "value": 1.0 },
    "base_sum":    { "type": "binary", "op": "+", "lhs": "char_val", "rhs": "weapon_val" },
    "pct_mult":    { "type": "binary", "op": "+", "lhs": "const_1", "rhs": "atk_pct" },
    "base_x_pct":  { "type": "binary", "op": "*", "lhs": "base_sum", "rhs": "pct_mult" },
    "final_atk":   { "type": "binary", "op": "+", "lhs": "base_x_pct", "rhs": "flat_val" }
  },
  "outputs": {
    "最终攻击力": { "node": "final_atk", "label": "最终攻击力", "is_primary": true }
  }
}
```

**节点类型速查表：**

| 类型 | 标识 | 说明 |
|------|------|------|
| 常量 | `const` | 固定数值，`"value": 3.14` |
| 变量引用 | `var` | 引用外部输入，`"path": "character.atk"` |
| 二元运算 | `binary` | `+` `-` `*` `/` `^` `min` `max` `mod` |
| 一元运算 | `unary` | `floor` `ceil` `abs` `sqrt` `neg` `ln` `log10` `sin` `cos` `tan` |
| 条件分支 | `condition` | 三输入：条件/真值/假值 |
| 表达式 | `expr` | 内联 Python 表达式，如 `"max(0, a - b)"`；支持比较 `< <= > >= == !=`、`and/or/not`（短路）与三元 `a if cond else b`（只求值选中分支） |
| 子图调用 | `call` | 引用另一个 subgraph，`"ref": "block_id"` |
| 输出标记 | `output` | 标记计算结果为输出 |

**输入控件（`ui_control`）**：变量可附带 `ui_control` 对象，由 `ComputeSheet` 传给控件：

```json
"user_input.damage_bonus": {
  "type": "float", "source": "user_input", "default": 0,
  "description": "伤害加成（%）",
  "ui_control": { "suffix": "%", "step": 1 }
}
```

- `suffix`：控件后缀（如 `%`）；`step`：步长；`min` / `max` 也可写在 `ui_control` 或变量顶层（`attr_schema` 同名字段优先）。
- **未声明 `max` 时不设业务上限**：float 上限为 `1e12`、int 上限为 `2_147_483_647`，不再使用 Qt 默认的 99.99 / 99。
- `type: "int"` 渲染为 `QSpinBox`（整数输入），`float` 渲染为 `QDoubleSpinBox`。
- 百分比口径：若公式按 `0–100` 存储，表达式需自行 `/100`；框架不做单位换算。

### 2.4 attr_schema.json — 变量属性描述

描述每个变量的 UI 展示方式（用于 ComputeSheet 自动推断控件）：

```json
{
  "attributes": [
    { "name": "character.base_atk", "type": "float", "source": "character",
      "default": 100, "description": "角色基础攻击力" },
    { "name": "weapon.base_atk", "type": "float", "source": "weapon",
      "default": 50, "description": "武器基础攻击力" }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `name` | 变量全路径，与 DAG variables 中的 key 一致 |
| `type` | `float` / `int` / `bool` |
| `source` | 来源分类，用于 UI 分组 |
| `default` | 默认值 |
| `description` | 展示说明 |

### 2.5 functions.py — 自定义纯函数

如果 DAG 内置节点不够用，可以注册自定义函数：

```python
# framework/adapters/your_game/functions.py

def clamp(value: float, low: float, high: float) -> float:
    return max(low, min(high, value))

def lerp(a: float, b: float, t: float) -> float:
    return a + (b - a) * t
```

在 `meta.json` 中注册后，DAG 节点可以通过 `"type": "call"` 引用：

```json
{
  "type": "call",
  "function": "clamp",
  "inputs": { "value": "some_node", "low": "const_0", "high": "const_100" }
}
```

### 2.6 UI 布局 — 告诉框架怎么展示

`layout.json` 定义计算器的界面结构。框架据此自动渲染控件：

```json
{
  "schema_version": "ui-v1",
  "sections": [
    {
      "id": "character",
      "type": "inputs",
      "title": "角色参数",
      "columns": 2,
      "variables": [
        "character.base_atk",
        "character.hp",
        "character.def"
      ]
    },
    {
      "id": "weapon",
      "type": "inputs",
      "title": "武器参数",
      "variables": [
        "weapon.base_atk",
        "weapon.atk_pct",
        "weapon.flat_atk"
      ]
    },
    {
      "id": "results",
      "type": "outputs",
      "title": "结算结果",
      "outputs": [
        "最终攻击力",
        "最终伤害"
      ]
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `type` | `inputs`（输入区）或 `outputs`（结果区） |
| `columns` | 拆列数（默认 1） |
| `variables` | 输入区的变量引用，与 DAG variables key 一致 |
| `outputs` | 结果区的输出引用，与 DAG outputs key 一致 |
| `tab` | 可选分页名；所有 section 必须同时指定（非空字符串）或同时省略，按首次出现顺序生成页签 |

> **分页**：任一 section 声明 `tab` 后，`ComputeSheet` 会用 `QTabWidget` 按 `tab` 首次出现顺序分组渲染；只写部分 section 会触发 `LayoutValidationError`（防止静默丢失分页）。典型用法是把可调输入与最终结果放「计算」页，把每个乘区的中间量放「乘区明细」页。

### 2.6.1 实体级联选择（`meta.entity_selectors`）

当单个数据文件记录很多（例如 571 条「舰船 × 武器」），一个平铺下拉难以查找。可在 `meta.json` 声明按字段逐级过滤的选择器：

```json
"entity_selectors": [
  {
    "source": "weapon",
    "data_file": "weapons",
    "steps": [
      { "field": "舰船分类", "label": "舰船种类" },
      { "field": "舰船", "label": "舰船" },
      { "field": "名称", "label": "武器", "display_field": "武器标签" }
    ]
  }
]
```

- `source`：注入 DAG 的命名空间（`weapon.*`）。
- `data_file`：`data/` 下的文件名（不含 `.json`）；缺省按 `character/weapon/equipment/enemy` 约定映射。
- `steps`：按顺序过滤的字段。字段值可为字符串或字符串列表；列表表示记录同时属于多个分类（如 `["护卫舰", "登陆舰"]`）。
- `display_field`：该级下拉显示文本；item data 仍保存 `field` 的值。最终一级的 item data 作为实体 `名称` 注入 context。
- 级联选择器会替代该 source 的普通平铺下拉；同一 `.calcpack` 可同时声明多个选择器。
- **等级输入自动隐藏**：仅当数据记录含非空数值列表字段（可按等级索引）时才显示等级框。舰船/武器等无等级数据不需要额外配置。

### 2.6.2 实体字段明细面板（`meta.entity_detail`）

在查看器最左列显示当前选中实体的字段明细，便于核对数据来源：

```json
"entity_detail": {
  "source": "weapon",
  "title": "武器数据",
  "sections": [
    {
      "title": "基础",
      "columns": 1,
      "fields": [
        { "field": "舰船", "label": "舰船" },
        { "field": "base_damage", "label": "基础单发", "format": ".1f" }
      ]
    }
  ]
}
```

- `source` 必须是已绑定非空 `data_files` 的实体来源；字段须至少出现在一条记录中。
- `columns` 为 1–3 的整数（默认 1）；`format` 为可选 Python 数值格式串（如 `.1f`）。
- 切换实体时面板自动刷新；缺少字段渲染为 `—`，列表值用 `、` 连接。
- 非法配置会被 `validate_adapter` 报为 `ENTITY_DETAIL_INVALID`，查看器则记录 warning 并跳过面板。

### 2.6.3 按实体灰显输入（`meta.entity_input_rules`）

不同实体可能让部分输入失去意义（例如不需要母舰的舰船无需填写母舰加成）。规则在选中实体字段匹配时禁用对应输入：

```json
"entity_input_rules": [
  {
    "source": "weapon",
    "field": "needs_mothership",
    "equals": 0,
    "disable": [
      "user_input.mothership_flight_bonus",
      "user_input.mothership_cooldown_bonus",
      "user_input.mothership_duration_bonus"
    ],
    "reason": "该舰船不需要母舰"
  }
]
```

- `disable` 只能引用生成后仍为 `user_input.*` 的变量；`equals` 支持数值、字符串与列表成员匹配。
- 实体记录**缺少该字段或值为空**时规则不命中，输入保持可编辑——用于「数据未知，留给玩家选择」。
- `reason` 可选，禁用后显示为控件与标签的悬停提示。
- 非法规则会被 `validate_adapter` 报为 `INPUT_RULE_INVALID`。

### 2.7 用 AI + MCP 构建适配包（可选）

本仓库内置 MCP 构建服务器，宿主 AI 可以直接完成「生成 → 校验 → 冒烟 → 打包」：

```powershell
cd calc-framework
pip install -r requirements-mcp.txt
python -m tools.calc_mcp --project-dir .
```

MCP 客户端（Claude Code / Cursor）配置：

```json
{
  "mcpServers": {
    "calc-framework-builder": {
      "command": "python",
      "args": ["-m", "tools.calc_mcp", "--project-dir", "."],
      "cwd": "${workspaceFolder}"
    }
  }
}
```

推荐让 AI 按以下顺序调用：

1. `list_templates` / `describe_schemas` — 选择模板并确认 DAG 字段。
2. `generate_adapter` — 用变量/公式步骤/输出生成适配包；复杂公式用 `scaffold_adapter` 提交完整 DAG。
3. `validate_adapter` — 修复所有 `errors`。
4. `smoke_test_adapter` — 用默认值或自定义 `context` 检查输出数值。
5. `export_calcpack` — 导出 `.calcpack`；`import_calcpack` 可回环验证。

**实体数据绑定（`data_files`）**：`generate_adapter` 可一次写入四类约定数据文件，变量由查看器实体下拉提供，不再作为手工输入：

```json
{
  "data_files": {
    "enemy": [
      {"名称": "测试敌人", "防御": 100, "韧性": [10, 20, 30]},
      {"名称": "高防敌人", "防御": 300}
    ]
  }
}
```

- 允许的键：`character` / `weapon` / `equipment` / `enemy`，分别写入 `data/characters.json` / `weapons.json` / `equipments.json` / `enemies.json`。
- 每条记录必须是对象且含非空字符串 `名称`，同一文件内 `名称` 不得重复；单文件 ≤2 MiB（按 UTF-8 字节）。
- **绑定规则**：`data_files` 中提供**非空记录列表**的来源视为已绑定，其变量保留 `source.name` 命名空间、由查看器实体下拉注入、不出现在输入区；未绑定或列表为空的来源，其变量生成时自动改写为 `user_input.<name>`，按原 source 分组显示在输入区（空列表会在 `warnings` 中提示）。
- 非空数据文件路径写入 `meta.entry_data`；`.calcpack` 导出自动携带 `data/`，格式不变。
- `validate_adapter` 会检查 `data/*.json`：记录须含非空 `名称` 且同文件不重复（否则报错）；空文件与无法映射到实体来源的文件名仅告警；`meta.entry_data` 引用的文件必须存在。
- `scaffold_adapter` 不接收 `data_files`：完整 DAG 含实体来源变量时，需用 `write_adapter_file` 自行写入 `data/*.json`，否则查看器没有实体下拉、变量不可编辑。
- 记录中的标量数值字段会扁平化为实体属性；数值列表按实体等级（1-indexed）取第 N 项；`名称`、`等级`、`类型` 等元数据字段被忽略。
- 变量 `name` 应与记录字段名一致（如 `防御` ↔ `"防御": 100`），否则查看器只能回退到变量默认值；`基础攻击力` 会自动映射为 `基础攻击`。
- `generate_adapter` 还接受 `entity_selectors`、`entity_detail` 与 `entity_input_rules`，契约分别见 §2.6.1–§2.6.3；三者都会写入 `meta.json` 并由 `validate_adapter` 校验（`SELECTOR_INVALID` / `ENTITY_DETAIL_INVALID` / `INPUT_RULE_INVALID`）。

**布局分页（`layout_sections`）**：`generate_adapter` 可用 `layout_sections` 一次生成带页签、列数与自定义分组的 `ui/layout.json`：

```json
{
  "layout_sections": [
    {"type": "inputs", "title": "输入参数", "source": "user_input", "tab": "计算"},
    {"type": "outputs", "title": "计算结果", "outputs": ["最终伤害"], "columns": 3, "tab": "计算"},
    {"type": "outputs", "title": "乘区明细", "outputs": ["基础乘区", "暴击乘区"], "columns": 3, "tab": "乘区明细"}
  ]
}
```

- inputs 段的 `variables`（裸变量名或 `user_input.<name>`）与 `source`（按原始来源收集未绑定实体变量）二选一；绑定实体变量与 `computed` 变量不能放进 inputs 段。
- outputs 段的 `outputs` 必须与 `outputs` 声明中的名称一致；变量/输出跨 section 重复会直接报错。
- `columns` 限 1–3（默认 2）；`tab` 必须所有 section 都写或都不写。
- 省略 `layout_sections` 时沿用自动 layout（按 source 分组 + 计算结果/中间过程两段）。
- 大文件可用 `read_adapter_file(offset=..., max_bytes=...)` 分页读取，按 `next_offset` 继续；默认单页 256 KiB，上限 2 MiB。

> 真实示例：`framework/adapters/wjdlglr/`（无尽的拉格朗日武器输出）最初按上述流程生成，
> 现已按八乘区口径 + 命中率乘区手工扩展（45 个变量 / 104 个节点 / 42 个输出），
> 并声明 `entity_selectors`、`entity_detail` 与 `entity_input_rules`。
> 武器属性与 Wiki 基础命中率来自 `data/weapons.json`（571 条「舰船 × 武器」记录），
> 查看器用「舰船种类 → 舰船 → 武器」三级联动下拉注入 `weapon.*`（`meta.entity_selectors`）；
> 命中率乘区：中间命中率 = (目标总闪避率 + 命中率加成) × (1 + 基础命中率)，
> 钳制到 5%–95% 后叠加服从 N(0, 0.03) 的浮动；维修/驻防/增益类武器固定 100% 命中。
> 配套测试见 `framework/tests/adapters/test_wjdlglr_*.py`（54 项）。

> 公式步骤引用变量 `name`、步骤 `id` 或数字字面量，**不要**写 `user_input.atk` 这类路径。
> `smoke_test_adapter` 会执行 `functions.py`，仅用于本地开发者适配包。详见
> [ADR-0028](adr/0028-mcp-builder-server.md)。

### 2.8 完整应用接入（桌面 / Web / VS Code）

适配包本身已能通过 `python -m calc_framework.ui.viewer framework/adapters/<id>` 或
`Game Calc Platform.exe --calcpack dist/<id>.calcpack` 打开。若要让它在三个面上与
endfield / arknights / wjdlglr 一致（启动器卡片、冻结 exe `--game`、Web 页面、VS Code 调试），
按下列注册点接入；**不需要**为每个游戏写专用 GUI。

| 面 | 注册点 | 说明 |
|----|--------|------|
| 桌面入口 | 新增 `games/<id>/main.py`（参照 `games/wjdlglr/main.py`） | 补 `sys.path` → `setup_logging` → `CalcPackViewer().load_adapter_dir(get_adapters_dir() / "<id>")`；应用身份 `CalcFramework.<Id>` |
| 启动器 | `framework/src/calc_framework/ui/launcher/runtime.py` | `_FULL_APP_SCRIPTS["<id>"] = "games/<id>/main.py"`；`launch_adapter_in_process` 增加同进程分支（加载失败返回 False 让 spawn 兜底） |
| 冻结 exe | `release_bundle/launcher_entry.py` | `--game` choices 与 `_launch_game` 增加分支；`release_bundle/release_layout.py` 的发布说明同步 |
| Web 后端 | 无需代码 | `meta.entry_data` 声明的数据由 `pack-bundle` / `data-summary` 通用返回；`GET /api/adapters/{目录id}/schema` 已按显示名加载 |
| Web 前端 | `web/frontend/src/App.tsx` | 懒加载 `AdapterGamePage`，新增 `<Route path="/<id>" element={<AdapterGamePage adapterId="<id>" />} />`；`useNavItems().gameItems` 增加导航项；`i18n/locales/{zh-CN,en}.ts` 增加 `nav.<id>` |
| VS Code | `.vscode/launch.json` | 增加 `program: ${workspaceFolder}/games/<id>/main.py` 的 debugpy 配置 |
| CI | `.github/workflows/ci.yml` | paths 增加 `"games/<id>/**"`，ruff 目录加入 `games/<id>/` |

**契约要求**：`meta.json` 的 `name` 是 Web 求值使用的适配器键（`POST /api/compute/evaluate` 的
`adapter` 字段）；数据文件必须在 `meta.entry_data` 中声明或放在 `data/*.json`；`layout.json`
所有 section 都写 `tab` 才会启用 Web 页签；DAG outputs 的 `label` / `format` 会用于 Web 输出
显示（支持 `.N%` 与 `.Nf`，空格式按 `.4f`）。

## 三、完整工作流——从公式到可运行计算器

### 步骤 1：用图编辑器可视化搭建 DAG

```bash
python -m calc_framework.graph_editor
python -m calc_framework.graph_editor path/to/graph.json   # 启动即加载
```

- 从左侧面板拖拽节点到画布
- 从输出端口连线到输入端口
- 双击复合节点进入子图
- 工具栏「运算」按钮实时求值
- 工具栏「保存」导出为 `.json`

也可直接手写 JSON（见 §2.3）。

### 步骤 2：用布局编辑器设计 UI

```bash
python -m calc_framework.editor --dag path/to/dag.json
```

布局编辑器读取 DAG 变量，三栏操作：
- **左栏**：DAG 变量列表
- **中栏**：Section 管理（添加/删除/排序输入输出节）
- **右栏**：变量拖拽到 Section，调整列数

完成 → 导出 `.calcpack`（ZIP 包，含 DAG + 布局 + 数据）。

### 步骤 3：用 CalcPackViewer 验证

```bash
devtool.py launcher

python -c "from calc_framework.ui.viewer import open_calcpack; open_calcpack('output/你的包.calcpack')"
```

CalcPackViewer 自动：
1. 读取 DAG 变量 → 渲染输入控件
2. 读取 UI 布局 → 组织 Section
3. 实时求值 → 显示所有输出
4. 支持实体选择（如果有数据文件）

## 四、进阶功能

### 4.1 复合节点与子图

复杂 DAG 可拆分为多个 subgraph：

```json
{
  "subgraphs": {
    "attack_block": {
      "parameters": ["base", "pct", "flat"],
      "nodes": {
        "sum": { "type": "binary", "op": "+", "lhs": "$base", "rhs": "$flat" },
        "result": { "type": "binary", "op": "*", "lhs": "sum", "rhs": "$pct" }
      },
      "output_node": "result"
    }
  },
  "nodes": {
    "atk": { "type": "call", "ref": "attack_block",
             "inputs": { "base": "char_val", "pct": "atk_pct_mult", "flat": "flat_val" } }
  }
}
```

### 4.2 插件系统

游戏专属的规则逻辑可以封装为框架插件：

```python
from calc_framework.plugin.base import BasePlugin, PluginMeta

class YourGameCritPlugin(BasePlugin):
    @property
    def meta(self) -> PluginMeta:
        return PluginMeta(
            name="your_crit",
            version="1.0.0",
            description="你的游戏暴击规则",
            author="你",
        )

    def on_load(self) -> dict:
        return {
            "variables": { ... },
            "templates": {
                "crit_template": {
                    "parameters": ["rate", "dmg"],
                    "nodes": { ... },
                    "output_node": "result"
                }
            }
        }
```

内置插件注册后，GUI 菜单「工具 → 插件管理器」可查看。

### 4.3 OCR 截图识装

如果你游戏有固定的 UI 布局，可以用 OCR 管线免去手动输入：

1. 采集游戏截图 → `python -m tools.ocr.cli` 检测
2. 在 `tools/ocr/recognizer.py` 的 `GAME_TERMS` 字典添加你的游戏专有名词
3. 修改 `mapper.py` 的 `_load_game_data()` 加载你的数据
4. GUI 底栏「截图识装」按钮一键填入

### 4.4 主题定制

适配包可以自带主题。在 `.calcpack` 中包含 `ui/theme.json`：

```json
{
  "name": "你的游戏主题",
  "base": "dark",
  "colors": {
    "bg_primary": "#1a1a2e",
    "accent": "#e94560"
  },
  "font": { "family": "SimHei", "size": 12 }
}
```

加载时自动注册为 `calcpack` 主题并激活。

### 4.5 数据文件

适配包的数据文件放在 `data/` 下。框架的 `AdapterPackage` 提供 `open_data(path)` 方法访问包内数据：

```python
adapter = AdapterPackage.load("你的游戏")
data = adapter.open_data("characters.json")
```

CalcPackViewer 加载 `.calcpack` 后，会自动读取其中的数据文件作为实体选择来源。

**约定文件名与查看器映射**（生成器与查看器共用 `calc_framework.data.entity_sources`）：

| 来源 | 数据文件 | 查看器下拉标签 |
|------|----------|----------------|
| `character` | `data/characters.json` | 角色 |
| `weapon` | `data/weapons.json` | 武器 |
| `equipment` | `data/equipments.json` | 装备 |
| `enemy` | `data/enemies.json` | 敌人 |

- 每个文件是记录数组；记录须含非空字符串 `名称`，同文件内不得重复（查看器按名称建索引，重复会静默覆盖，故生成期即拦截）。
- 记录中的标量数值字段（int/float）扁平化为实体属性；数值列表按等级取第 N 项（1-indexed，超出取最后一项）；`名称`、`等级`、`类型`、`星级` 等元数据字段忽略。
- 生成器仅在 `meta.entry_data` 中列入非空数据文件路径；手工维护适配包时建议保持一致。
- 单文件上限 2 MiB（UTF-8 字节）；`generate_adapter` 与 `ProjectScope.write_text` 双重校验。
- 级联选择所需字段（如 `舰船分类` 列表、`武器标签`）直接写在记录里；`meta.entity_selectors` 只做声明，不改变数据文件格式。

### card_rpg（最简单的参考）

```
framework/adapters/card_rpg/
├── meta.json
├── card_rpg.dag.json      # 攻击 - 防御 = 伤害
```

```
└── ui/
    └── layout.json
```

核心公式：`实际伤害 = 面板攻击 × 技能加成 × (1 - 护甲/(护甲+100))`

## 七、常见问题

**Q：需要修改框架核心代码吗？**
不需要。适配包是纯配置 + 自定义函数，框架自动发现和加载。

**Q：DAG 支持循环引用吗？**
不支持。DAG 是有向无环图，引擎执行拓扑排序，含循环时会报错。

**Q：可以在一个适配包中使用多个 DAG 文件吗？**
可以。用 `entry_dag` 指定主图，主图通过 `call` 节点引用其他图。

**Q：如何调试 DAG 求值结果？**
图编辑器工具栏「运算」按钮显示全部节点值，属性面板底部显示选中节点的实时预览。

**Q：框架和我的游戏如何分发？**
- 框架：`pip install calc-framework` 或直接复制 `framework/` 目录
- 适配包：独立目录，复制到 `framework/adapters/` 下即可
- 用户打包：`main_editor.py` 导出 `.calcpack` 供 CalcPackViewer 加载
