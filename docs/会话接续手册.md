## 1. 项目是什么

《终末地》伤害相关 **桌面 GUI 计算器**（PySide6） + **终末地数据设计器**（data editor / formula inverter）。

### 计算器能力

- 选角色/武器、等级、潜能、信赖与**左侧技能等级** → 角色/武器属性列 + **右侧乘区**（15 乘区链，框架 ComputeSheet DAG 驱动，9 节 layout 全部 22 个输出）
- **单段伤害**、**乘区快照**、单/多技能**快速预览**（装备采样，非全量）
- **全量遍历**：单技能或（开启「使用手动次数」时）**多技能段级加权总伤** TopN 弹窗；预计组合数/耗时、并行线程（默认逻辑核−1）、可取消；**MVP 导出/续跑**（`search_output/`）
- **双页签 GUI**：**计算页**（五列主视图 + 快速确认）与 **高级页**（操作 / 全量搜索 / 多技能）；顶部页签 +「前往高级页 / 返回计算页」
- **固定配装**：高级页可勾选 0–4 件具体装备，未勾选部位在候选范围内遍历
- **工具与分享**（高级页）：配装 JSON 导入/导出、操作日志、计算历史、伤害仪表盘（matplotlib）、**敌方参数面板**（防御/抗性/失衡易伤完整微调）、多方案对比
- **SearchEngine 框架化**：`EndfieldSearchEngine` 适配器包装搜索流水线，`SearchRunner.run_with_engine()` 消费
- 数据：`characters.json` / `weapons.json` / `equipments.json`；BWIKI 工具链可同步

### 设计器能力

- **公式反推**：输入属性 90 级 / 技能 9–12 级数据反推成长公式
- **数据编辑**：图形化新增/编辑/删除角色、武器、装备，保存后自动刷新缓存
- **数据浏览**：查看角色/武器/装备 JSON 列表

### 三目标打包

`scripts/main_build.py --target calculator`（计算器，含 matplotlib 仪表盘 + OCR 可选）、
`scripts/main_build.py --target designer`（数据设计器，公式反推 + 数据浏览/编辑）和
`scripts/main_build.py --target pack-designer`（配置包设计器，三页签布局编辑 + .calcpack 导出，不含 JSON 数据）。

**尚无**：单 exe 统一入口、自动更新机制、在线插件市场、NSIS 安装包（见 §4 P3）。

## 2. 用户要求与产品约定（接续时勿忘）

| **结构** | 大范围重构以**可导航**为目标；新代码禁止在已超限目录继续平铺；见 ADR-0001 |
| **GitHub** | **默认由人类**在 `[根]` 跑 `python github_upload_module.py`；Agent 勿裸 `git push`，除非当次明确要求上传。**排障必读** [`docs/上传脚本与-pre-commit.md`](上传脚本与-pre-commit.md) |

| **手册** | 较大功能完成后提醒人类更新本文 §3–§4 与文首日期 |

### 2.2 全量搜索（配装枚举）

| 项 | 约定 |
|----|------|
| **装备词条** | 搜索必须计入 `属性词条`（战技/连携/终结伤害%、四维、攻击力% 等），不能只读 `效果`/`三件套效果` |
| **剪枝「无益」** | `prune_non_beneficial`：无效果文案且**无** `属性词条` 的装备剔除 |
| **优先级排序** | 按角色**主能力/副能力**与目标**技能类型**对装备排序（**不减少组合总数**） |
| **固定配装** | 高级页「固定配装（0–4 件）」：勾选部位并选具体装备则固定；**未勾选**部位在「装备范围」过滤后的 catalog 内**全部遍历**（`FixedLoadoutSelection` + `gui/fixed_loadout_controls.py`） |
| **评分：单技能** | 未开「使用手动次数」：按左侧**当前选中技能**的单段伤害 TopN |
| **评分：多技能** | 已开「使用手动次数」且段级次数不全为 0：TopN 按 **Σ(各段单段伤害 × 次数)**（键如 `连携技:1`）；`evaluate_multi_skill_task`；弹窗/预览/仪表盘可展示段级分项 |
| **预计 vs 进度** | 与 `optimizer_config_for_character` + `fixed_loadout` 一致；改固定件/次数/范围后**勿用旧 `search_runs.db` 续跑对比** |
| **武器/装备范围** | 与 GUI「武器候选范围」「装备范围」一致；技能倍率来自左侧技能等级 |

### 2.3 多技能快速预览与段级次数

| 项 | 约定 |
|----|------|
| **段级次数** | GUI 按角色 JSON **各段倍率**动态生成行（如「连携技 第1段」「第2段」）；次数键 **`战技:1`**、**`连携技:2`** 等 |
| **总伤** | **Σ(段单次伤害 × 次数)**；支持「2×段1 + 1×段2」；**默认全 0**，只填需要计入的段 |
| **预设兼容** | 旧 `{"连携技": 2}` 导入时归一为 `{"连携技:1": 2}`（`skill_segments.normalize_manual_segment_counts`） |
| **技能倍率** | 来自左侧战技/连携/终结**等级** + 段索引；仅等级>0 且该段倍率有效时进入场景 |
| **默认** | 未开「手动次数」：快速预览为当前选中技能 ×1；**全量**仍按 §2.2 单技能评分 |
| **全量** | 开「手动次数」且至少一段次数>0：**快速预览、全量遍历、MVP** 均按段级加权总伤 |
| **开关刷新** | 切换「使用手动次数」走轻量刷新（`_suppress_full_confirm_refresh`），避免整窗 destroy 闪屏 |

### 2.4 GUI 体验

| 项 | 约定 |
|----|------|
| **字体** | 与系统一致（`utils/gui_fonts.py`，`TkDefaultFont`） |
| **启动** | 最大化（`utils/gui_window.py`，Windows `zoomed`）；启动页策略见 `ui_preferences.py`（默认总是计算页） |
| **双页签** | 顶层 `CTkTabview`：**计算页** + **高级页**；切页不重建控件、不丢输入；关闭时保存 `ui_preferences.json` |
| **计算页** | 五列主视图（`APP_COLUMN_WEIGHTS = (0,0,1,1,0)`）；角色/武器选择用**普通容器**（非 Scrollable）；乘区下方 **确认选择 + 前往高级页** |
| **高级页** | 原底栏三列迁入：**操作 / 全量搜索 / 多技能次数**（宽屏搜索:多技能 **2:3**；窄屏第二行 **2:3**）；窄屏（`<1480px`）自动两行重排 |
| **折叠降噪** | 角色侧 **信赖**在主区 + **技能等级**折叠；武器侧 **武器技能**折叠（内分普通/特殊技能）；两侧默认展开、关应用记住状态 |
| **按钮尺寸** | `PRIMARY_ACTION_BUTTON_HEIGHT=40` / `SECONDARY_ACTION_BUTTON_HEIGHT=32` |
| **确认刷新** | `confirm_refresh.py`：输入签名未变不重绘三列；最小化/失焦不触发整页清空；「确认选择」可 `force` 刷新 |
| **内置说明书** | 所有 GUI 均包含结构化帮助对话框（F1 或「帮助」菜单/按钮），左侧分类树导航 + 右侧 HTML 内容。无法上网时也能正常使用。 |
| **待确认配装** | `loadout_pending.py`：等级/信赖/技能/武器词条/高级页计算选项等改动**不自动**刷新三列；换角色/武器名仍即时刷新；两枚「确认选择」同步显示「待更新」；启动与预设导入仍 `force` 确认 |
| **武器特殊能力** | 界面只显示**效果词条**（如 `寒冷伤害+`），不展示触发条件；`extract_effect_display_name()`，计算仍用完整名 |
| **武器词条展示** | `display_lines.weapon_bonus_display_uses_percent`：**附加攻击力+**、四维+、主/副能力+ 为**固定整数**；**攻击力+**、*伤害+、*率+、充能效率 带 `%`（与 `final_attack_zone` 一致） |

**计算页（`MAIN_CONTENT_ROW=0`，五列）**：

| 区域 | 内容 | 说明 |
|------|------|------|
| 列 0–1 | 角色/武器选择 | min ~260px；角色 **信赖**主区 + **技能等级**；武器 **武器技能**（普通/特殊） |
| 列 2–3 | 角色/武器属性 | **可伸缩** |
| 列 4 | 乘区数据 | **固定宽约 340px**；底部快速操作行 |

**高级页（`CONTROL_DOCK_ROW=1` 语义复用为高级页 body 行）**：

| 区域 | 内容 | 说明 |
|------|------|------|
| 左 | 返回、确认、计算模式、**工具与分享** | 「更多设置」折叠：导入导出/分析/维护/启动页策略 |
| 中 | 全量遍历、固定配装、预估、MVP | hint 框固定行高 |
| 右 | **多技能次数**（段级 + 手动开关） | 段列表外层定高 + 内层 Scrollable（**勿**对 Scrollable 调 `grid_propagate(False)`） |

### 4.98 修复 PyInstaller 闪退 + Web 下载不通（2026-06-01，已完成）

**背景**：首次打包的 exe 解压后双击闪退；Web 下载按钮点击后页面刷新无响应。

**问题清单**：

| 问题 | 根因 | 修复 |
|------|------|------|
| exe 闪退 `ModuleNotFoundError: No module named 'web.backend'` | `web` 不是标准 Python 包（无 `__init__.py`），PyInstaller 冻结导入系统无法解析命名空间包 | [run_packaged_main.py](file:///e:/endfield_damage_calculator/web/backend/run_packaged_main.py): `import web.backend.main` → `import main` + 把 `_internal/web/backend` 加入 `sys.path` |
| 下载按钮点击后页面刷新 | MUI `<Button href>` 被 React Router 客户端路由拦截 | [SearchPanel.tsx](file:///e:/endfield_damage_calculator/web/frontend/src/components/calculator/SearchPanel.tsx): `href` → `onClick` + `window.location.href` |
| `/api/download/client` 返回 SPA HTML | 部署脚本只上传前端 dist/，后端 Python 文件未同步到服务器 | [deploy_pythonanywhere.py](file:///e:/endfield_damage_calculator/web/scripts/deploy_pythonanywhere.py): 新增 `_upload_backend_files()` 上传 `web/backend/` 全部 .py 文件 |
| 中文 Content-Disposition 乱码 | HTTP 头中非 ASCII 字符编码问题 | 改用纯英文 `local-backend.zip` 文件名 |
| `async def` + `StreamingResponse(BytesIO)` 不稳定 | PythonAnywhere WSGI + `a2wsgi` 对 async stream 支持不佳 | 改用 `def` + `Response(content=bytes)` + `Content-Length` |
| 下载仍是占位文件（304 字节） | 实际 PyInstaller exe 未构建 | 本地运行 PyInstaller 构建实际 exe（39 MB）后重新部署 |

**关键教训（已写入 `.trae/rules/project_rules.md`）**：
1. PyInstaller 入口点不能使用命名空间包导入（`web.backend.main`）
2. `--onedir` 模式下 `sys._MEIPASS` = exe 目录，编译模块在 `_internal/`
3. 前端下载链接必须用 `onClick` + `window.location.href` 绕过 React Router
4. 部署脚本必须上传后端 Python 文件，不能假设 git 同步
5. HTTP 响应头文件名必须用 ASCII

### 4.99 显式导入原则写入规范（2026-06-01，已完成）

**背景**：PyInstaller 命名空间包故障揭示了一个根本性的代码设计缺陷——`import _path_setup` 这种"裸导入"依赖文件恰好就在 `sys.path` 上，而不是通过显式的包路径来引用。如果入口文件只导入 `_path_setup` 而不通过包机制，PyInstaller 的冻结导入系统无法追溯这个依赖。

**修复**：

| 文件 | 改动 | 说明 |
|------|------|------|
| `web/backend/__init__.py` | **新建** | 使 `web/backend/` 成为标准 Python 包，支持相对导入 |
| `web/backend/main.py` | `import _path_setup` → `from . import _path_setup` | 显式相对导入，导入图可追溯 |
| `web/backend/asgi.py` | `from main import app` → `from .main import app` | 同上 |

**写入规范的文档**：

| 文档 | 新增内容 |
|------|----------|
| `.trae/rules/project_rules.md` | 新增「Python 模块导入规范（显式导入原则）」节，含 6 条规则 + 场景表 + 检查脚本 |
| `docs/代码结构规范.md` | §3 新增第 11 条导入规范（包内相对导入/入口绝对导入/__init__.py/交叉引用层次）+ §6 自检清单新增导入检查项 |
| `docs/adr/0021-remove-sys-path-hacks.md` | 更新导入语句 `from _path_setup import *` → `from . import _path_setup`；标注 web/backend/ 已成为标准包 |

**核心原则**：每个 Python 文件必须通过**显式、可追溯的 import 路径**被引用。禁止依赖"恰好就在 sys.path 上"的隐式导入。

**Arknights 核心伤害公式**：

```
物理最终伤害 = (基础ATK × 技能倍率 - DEF) × 伤害倍率增益
  其中：基础ATK = 面板ATK + 潜能ATK + 信赖ATK
        技能倍率 = 技能等级倍率（1-7/M1/M2/M3）× 其他攻击力提升效果
        DEF = 目标DEF × (1 - 百分比减防) - 固定减防
        伤害倍率增益 = (1 + 所有伤害加成百分比)

法术最终伤害 = (基础ATK × 技能倍率) × (1 - RES有效值) × 伤害倍率增益
  其中：RES有效值 = (目标RES - 固定减法抗性) × (1 - 百分比减法抗性)
        伤害倍率增益同上

真伤最终伤害 = 基础ATK × 技能倍率
```

### 4.116 搜索内存优化 + 代码来源检查工具链重构（2026-06-02，已完成）

**背景**：搜索功能在全量遍历时内存占用过高（100 万组合物化 ~1.3GB）；`scancode` 扫描会撑爆内存；用户需要权威的 AI 代码抄袭检测工具。

**搜索内存优化**（3 个框架层文件修改）：

| 问题 | 原因 | 修复 |
|------|------|------|
| 候选任务全部物化 | `generate_candidates()` 用 `list(tasks)` 将迭代器转为列表 | 返回类型改为 `Iterable[C]`，直接透传生成器 |
| 并行执行器累积全部结果 | `run_parallel()` 的 `results.append(result)` 累积所有评分结果 | 有 `top_n_tracker` 时跳过累积，只保留 Top-N |
| 持久化层用 `len()` | `_run_with_persist` 中 `len(candidates)` 对迭代器无效 | 单次遍历构建 `pending` 并同步计数 |

**效果**：100 万组合从 ~1.3GB → 接近 0（流式生成 + 仅 Top-N 保留）。

**代码来源检查工具链**：

| 工具 | 用途 | 位置 |
|------|------|------|
| `run_scancode.py` | 权威许可证/版权扫描（逐个目录，--processes 16） | `tools/run_scancode.py` |
| `check_code_origin.py` | 轻量 SPDX/版权头快速检查（1 秒，50 MB） | `tools/check_code_origin.py`（新建） |

**scancode 使用教训**：
1. **不要用 `--ignore`** 扫描全仓库——`--ignore` 触发极慢的预扫描阶段（10+ 分钟），且容易意外匹配过多文件
2. **只扫源代码目录**：指定具体目录路径，不使用 `--ignore`
3. **限制并行进程**：`--processes N` 限制并行数。本机 24 线程，默认启动 24 进程 → 3.6 GB 峰值；限制为 `--processes 16`（物理核心数）→ 2.4 GB
4. **波浪式内存正常**：多进程每批文件处理完释放内存再处理下一批，不是泄漏

### §4.121 P5-A-1：BWIKI 增量同步（2026-06-02，已完成）

**背景**：每次运行 `python -m tools.bwiki_scout --apply` 时，对所有已知干员/武器重新解析完整的 wikitext → 反推成长曲线 → 重新写入 JSON。如果大多数实体 Wiki 数据未变化，这个过程浪费计算资源。

**方案**：引入基于内容哈希的增量同步机制。

**变更内容**：

| 文件 | 操作 | 说明 |
|------|------|------|
| `tools/bwiki_scout/incremental_sync.py` | **新建** | 核心增量状态管理：`load_sync_state()`、`save_sync_state()`、`content_changed()`、`record_entity_sync_batch()`、`cleanup_stale_entities()`、`get_stale_entities_from_cache()` |

| `tools/bwiki_scout/sync_all.py` | **修改** | 新增 `--full` 命令行参数（默认增量，`--full` 时全量重新处理） |
| `tools/bwiki_scout/__main__.py` | **修改** | docstring 新增 `--full` 用法示例 |

**工作方式**：
1. 每次成功同步后，记录每条目 wikitext + html 的 SHA256 哈希到 `output/sync_state.json`
2. 下次同步前，比较当前缓存内容的哈希值
3. 哈希不变的条目跳过（无需重新解析/反推/写入）
4. 哈希变化 / 新增缓存 / 首次同步的条目进入同步队列

**CLI 用法**：

### §4.137 本会话：装备 Bug 修复——BWIKI 散件装备缺失（2026-06-03，已完成）

**背景**：用户报告从 BWIKI 爬取的终末地装备数据缺少非套装装备（散件）。调查发现 BWIKI 将所有装备（包括无套装效果的散件）都赋予 `所属套组` 字段，但通过 `装备套组效果` 是否为空可以区分真套装装备与散件。

- 修复前这些散件被错误标记为套装装备

**修复**：
1. `equipment_wiki.py`：先收集套装效果（`效果` + `三件套效果`），如果两者都为空，则将 `套装` 字段设为空字符串
2. `games/endfield/data/equipments.json`：回填修复 34 件散件装备的 `套装` 字段置空（四号谷地 30 件 + 武陵 4 件）
3. GUI 的「仅散件装备」过滤器（`equipment_filters.py:74`）使用 `not str(row.get("套装") or "").strip()` 逻辑，已能正确识别这些散件

| 乘区 | 公式 | 输入参数 |
|------|------|----------|
| 基础伤害区 | 最终攻击力 × 技能倍率 | 最终攻击力(1000), 技能倍率(1.0) |
| 暴击区 | 1 + 暴击率×(暴击伤害-1) | 暴击率(0.05), 暴击伤害(0.5) |
| 伤害加成区 | 1 + 伤害类型 + 技能类型 + 失衡 + 其他 | 4 种加成(0.0) |
| 伤害减免区 | 1 - 减免总值 | 减免值(0.0) |
| 增幅区 | 1 + 增幅总值 | 增幅(0.0) |
| 虚弱区 | 1 - 虚弱总值 | 虚弱(0.0) |
| 庇护区 | 1 - 庇护值 | 庇护(0.0) |
| 脆弱区 | 1 + 脆弱总值 | 脆弱(0.0) |
| 易伤区 | 1 + 易伤总值 | 易伤(0.0) |
| 防御区 | 100 / (100 + 敌方防御) | 敌方防御(200) |
| 失衡易伤区 | 失衡易伤系数 | 系数(1.0) |
| 抗性区 | 1 - (抗性-无视)/100 | 抗性(20), 无视(0) |

| 连击增伤区 | 1 + 连击增伤 | 连击增伤(0.0) |
| 特殊乘区 | 特殊乘区系数 | 系数(1.0) |

**链图结构**：`const(1.0) × [复合:基础伤害区] × [复合:暴击区] × ... × [复合:特殊乘区] = 最终伤害`

### 4.64 P1：通用展示层 CalcPackViewer（2026-05-30）

**新文件**：`framework/src/calc_framework/ui/viewer.py` — 通用的用户展示层，作为独立的桌面应用运行。

**核心功能**：
1. **加载 .calcpack**：通过 `_load_calcpack()` 解压 ZIP → 解析 meta/dag/layout/theme/data
2. **实体选择**：左侧面板显示「等级」控件 + 「角色」「武器」「装备」下拉框（从 data/*.json 自动填充）

4. **ComputeSheet 渲染**：通过 `_rebuild_sheet()` 创建 ComputeSheet，`computed` 源变量自动提升为 `user_input` 控件
5. **实时求值**：实体切换/等级变更/参数修改后自动重新求值
6. **主题应用**：从 `ui/theme.json` 读取深色主题并应用 `setStyleSheet()`

**关键实现细节**：

| 组件 | 说明 |

| `CalcPackViewer` | QMainWindow，三栏布局（左实体选择 / 中 ComputeSheet / 右包信息） |

| `_FALLBACK_DEFAULTS` | computed 变量缺失默认值时的后备（如 `技能倍率: 1.0`, `特殊乘区: 1.0`） |
| `_rebuild_sheet()` | 将 `computed` 源变量 patch 为 `user_input`，使 ComputeSheet 渲染为可调控件 |
| `main()` | CLI 入口，支持 `python -m calc_framework.ui [path.calcpack]` |
