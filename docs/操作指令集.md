## 1. 首次 / 换电脑必做

### 1.1 Python 与依赖

```powershell
cd endfield_damage_calculator\endfield_damage_calculator   # [包]
pip install -e ".[dev]"
```

| 作用 | 说明 |
|------|------|
| 可编辑安装 | 代码改动立即生效，无需重复安装 |
| `[dev]` | 含 `pytest`、`pyyaml` 等；GUI 运行时依赖（含 `matplotlib`）已随 `pip install -e .` 安装 |
| `[build]` | 含 `pyinstaller`，仅打包 exe 时需要（`python build.py`） |

```powershell
pip install -e ".[dev,build]"   # 开发 + 打包一次装齐
```

### 1.2 SSH（推送 / 拉取 GitHub）

1. 生成密钥并添加到 GitHub → Settings → SSH keys  
2. 若 22 端口不通，在 `~/.ssh/config` 配置：

```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
```

3. 验证：`ssh -T git@github.com`

| 作用 | 说明 |
|------|------|
| 免 Token | `git remote` 使用 `git@github.com:...`，勿把 PAT 写进 URL |

### 1.3 GitHub Issues 与 CLI（可选）

**Web 提交（推荐）**：打开仓库 **Issues → New issue**，选择模板：

| 模板 | 适用 |
|------|------|
| **Bug 报告** | 异常行为、复现步骤、期望 vs 实际、截图/日志、环境信息 |
| **功能建议** | 新功能或体验改进（非 Bug） |

模板文件位于 `[根]/.github/ISSUE_TEMPLATE/`。新建 Bug 默认带 `needs-triage` 标签。

```powershell
# [根] 或任意已 clone 目录
gh auth login
gh issue list
gh issue create --web                    # 浏览器里选模板
# gh issue create --template bug_report.yml   # 部分 gh 版本支持
```

| 作用 | 说明 |
|------|------|
| 管理 Issue | 与 [`docs/agents/issue-tracker.md`](agents/issue-tracker.md)、[`triage-labels.md`](agents/triage-labels.md) 一致 |
| 查看单条 | `gh issue view <编号> --comments` |
| 分拣标签 | `gh issue edit <编号> --add-label ready-for-agent` |

### 1.4 版本号在哪里改

| 变量 | 文件 | 谁改 |
|------|------|------|
| `_VERSION` | `[包]/please_read_me.py` | 上传脚本自动 bump；**build.py 横幅「源码包版本」** |
| `_EXE_VERSION` | 同上 | **窗口标题**与 exe 内版本；**改后须重新 `build.py`**；上传脚本不改 |

上传流程细则见 `[包]/please_read_me.py` 内 `UPLOAD_WORKFLOW`，或本文 [§5](#5-github-上传与下载仓库根)。

### 1.5 提交签名（可选，GitHub Verified）

在 GitHub → **Settings → SSH and GPG keys** 添加密钥后，本机例如：

```powershell
git config --global gpg.format ssh
git config --global user.signingkey C:/Users/你的用户名/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
```

| 作用 | 说明 |
|------|------|
| 上传脚本 | 检测上述配置；有 `commit.gpgsign` 则自动签，仅有 `user.signingkey` 则用 `git commit -S` |
| 未配置 | 脚本打印设置提示；commit 仍可进行，但 GitHub 可能无 **Verified** |
| 历史提交 | 旧 commit 不会补签 |

## 5. GitHub 上传与下载（`[根]`）

### 5.1 上传（推荐日常用这个）

```powershell
cd endfield_damage_calculator   # [根]
python github_upload_module.py
python github_upload_module.py --minor      # 第二位 +1：新武器/新乘区等
python github_upload_module.py --no-bump    # 提交推送但不改 _VERSION
```

| 步骤 | 作用 |
|------|------|
| 检测业务改动 | 仅有 `please_read_me.py` 改动时不 bump |
| 交互 P/M | 回车 = patch（第三位 +1）；输入 `M` = minor |
| 写总结块 | 在 `please_read_me.py` **底部**生成 `# --- UPLOAD_SUMMARY ---` |
| commit | 消息形如 `v1.9.1: 标题` + 改动列表（读总结块） |
| 提交签名 | 若本机已配置 `commit.gpgsign` 或 `user.signingkey`，脚本自动签名（后者用 `git commit -S`）；未配置会提示如何设置，以便 GitHub 显示 **Verified** |
| push 成功 | 删除底部总结块；**失败则保留**，版本不回滚 |
| 纯补推 | 仅有未 push 的 commit、无新改动 → **不** bump、不写总结 |

**不要**用裸 `git commit` + `git push` 代替上传脚本，否则 `_VERSION` 可能与远程不同步。

### 5.2 从远程覆盖本地（危险）

```powershell
cd e:\endfield_damage_calculator   # [根]
python github_download_module.py
```

| 作用 | 说明 |
|------|------|
| 强制同步 | `reset --hard` 到 `origin/main`，**未提交改动会丢失** |
| 安全确认 | 运行后须完整输入 **`覆盖本地`** 才会执行；否则会取消且不改本地 |
| 未跟踪文件 | 还会执行 `git clean -fd`，未纳入 Git 的文件/目录也会删除 |
| 使用场景 | 换电脑、本地搞乱只想与远程完全一致 |
| 跳过确认 | `python github_download_module.py --yes`（仅脚本/自动化，慎用） |

覆盖前若有重要本地改动，请先 `git stash push -u -m "备份"` 或走上传脚本提交，**不要**在未备份时输入确认词。

### 5.3 手动 Git（了解即可）

| 命令 | 作用 |
|------|------|
| `git status` | 查看改动 |
| `git remote -v` | 应显示 `git@github.com:...`，无嵌入 Token |
| `git push` | 仅补推时可用；新功能提交仍建议走上传脚本 |

## 7. 打包发布（`[包]`，软件与数据分文件夹）

许可上 **软件（LICENSE）** 与 **游戏数据（DATA_LICENSE）** 分开授权；发布时建议物理分离：exe 不内嵌 JSON，便于附带 `DATA_LICENSE` 并单独更新数据。非商业场景仍可「文件夹内 exe + JSON」一并分发（见 [`docs/数据来源与许可.md`](数据来源与许可.md) 情形对照）。

### 7.1 打包前

1. 在 `please_read_me.py` **手动**修改 `_EXE_VERSION`（窗口标题与 exe 用户可见版本）  
2. 确认运行时 + 打包依赖：`pip install -e ".[build]"`（或 `".[dev,build]"`）  
3. **重新** `python build.py`（仅改 `_EXE_VERSION` 不会更新已有 dist/exe，必须重打包）  
4. `[包]` 自检：`python build.py` 开头应显示「目标 EXE v…」与 `_EXE_VERSION` 一致

| 打包要点 | 说明 |
|----------|------|
| Windows WMI | `build.py` / `release_bundle/pyinstaller_entry.py` 在 import PyInstaller 前打 `platform_win32_patch`；**所有顶层 import CTk 的 GUI 子模块**亦须在 import 前打补丁（PyInstaller Analysis 会单独 import） |
| matplotlib | 打包前须已安装；`--collect-all matplotlib` + `hidden-import backend_tkagg`（仪表盘） |
| 看门狗 | 默认超时 1200s、心跳 15s；可设 `ENDFIELD_BUILD_TIMEOUT_SECONDS` / `ENDFIELD_BUILD_HEARTBEAT_SECONDS` |
| 数据 | JSON **不**写入 exe；`stage_release_folder` 复制到 `dist/终末地伤害计算器/` |

### 7.2 执行打包

```powershell
cd endfield_damage_calculator\endfield_damage_calculator   # [包]
python build.py
```

可选（打包较慢或机器较慢时延长超时）：

```powershell
$env:ENDFIELD_BUILD_TIMEOUT_SECONDS='1800'
$env:ENDFIELD_BUILD_HEARTBEAT_SECONDS='15'
python -u build.py
```

| 作用 | 说明 |
|------|------|
| 输出 | **`dist/终末地伤害计算器/`** 整个文件夹（勿只发 exe） |
| 内含 | `终末地伤害计算器.exe`、`character_weapon_equipment/**/*.json`（含 `equipments.json`）、`DATA_LICENSE`、`LICENSE`、`NOTICES.md`、`发布说明.txt` |
| 加载 | exe 从**同级目录**读取 JSON（`utils.path_utils.get_resource_path`） |
| 搜索导出 | 全量/MVP 结果写入发布文件夹内 **`search_output/`**（与 exe 同级，非 C 盘临时目录）；详见 `发布说明.txt` |
| 勿提交 | `dist/`、`*.exe` 已在 `.gitignore` |

分发 zip 时请压缩 **`终末地伤害计算器` 文件夹**，不要只提取 exe。

`_VERSION` 与 exe 版本**独立**：上传 GitHub 不会改 `_EXE_VERSION`。

| `output/reports/stats_diff.md` | 干员 1–90 级对比（`干员名/详细数据` wikitext） |

| [`tools/bwiki_scout/CACHE.md`](../tools/bwiki_scout/CACHE.md) | 缓存续跑与备份 |

`scout.py` 会为每名干员额外拉取 **`干员名/详细数据`** 子页。

### 9.2 Wiki 数据来源（同步时）

| 本地字段 | Wiki 来源 |
|----------|-----------|
| 干员四维、基础攻击力（90 级） | `raw/<干员>/详细数据/wikitext.txt`（模板 `干员/逐级等级`） |
| 战技 / 连携 / 终结技倍率 | `raw/<干员>/html.html` 技能区各 tab 的「伤害倍率」行（12 级） |
| 武器基础攻击力（90 级） | `raw/<武器>/wikitext.txt` 的 `基础攻击力`、`满级基础攻击力` |
| 武器附加属性、特殊能力 | 同页 `词条1rank1–9`、`词条2rank…`、`词条3副1rank…`（须含完整成长块） |
| 装备部位/套装/效果文本 | `output/parsed/equipment.json`（`parse_draft.py` 生成） |

无 `词条1rank1` 等字段的武器页（如部分低星 Wiki 简表）会被 `sync_weapons.py` 跳过。

### 9.3 同步到本地 JSON / seed（预览 → 写入）

```powershell
# 干员：characters.json + endfield_damage_calculator/scripts/seed_characters.py

python tools/bwiki_scout/sync_operators.py --new          # 导入本地尚无的新干员（须先 scout）

# 武器：weapons.json + scripts/seed_weapons.py（仅 Wiki 含 rank 成长块者）
python tools/bwiki_scout/sync_weapons.py
python tools/bwiki_scout/sync_weapons.py --apply
python tools/bwiki_scout/sync_weapons.py --new              # 预览可导入的新武器
python tools/bwiki_scout/sync_weapons.py --new --apply      # 写入新武器 + 更新 seed

# 装备：equipment_data/equipments.json（基于 parsed/equipment.json）
python tools/bwiki_scout/sync_equipments.py
python tools/bwiki_scout/sync_equipments.py --apply

# 一键：干员 + 武器 + 装备
python tools/bwiki_scout/sync_all.py
python tools/bwiki_scout/sync_all.py --apply
python tools/bwiki_scout/sync_all.py --apply --new
```

反推使用包内 `calculation.inverse`（与手动 seed 录入同一套公式）。须遵守 Wiki 条款与 [`DATA_LICENSE`](../DATA_LICENSE)；**商用不可用**本仓库数据或侦察/同步流程产出。
