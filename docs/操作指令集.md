## 1. 首次 / 换电脑必做

### 1.1 Python 与依赖

#### venv 创建（首次/重建）

```powershell
# ⚠️ 重要：创建 venv 前必须先设编码，否则 pip install 可能损坏 Unicode 文件
$env:PYTHONUTF8 = "1"
chcp 65001 > $null

python -m venv .venv
.venv\Scripts\activate
```

#### 安装依赖

```powershell
cd games/endfield   # [包]
pip install -e ".[dev]"
```

| 作用 | 说明 |
|------|------|
| 可编辑安装 | 代码改动立即生效，无需重复安装 |
| `[dev]` | 含 `pytest`、`pyyaml` 等；GUI 运行时依赖（含 `matplotlib`）已随 `pip install -e .` 安装 |
| `[build]` | 含 `pyinstaller`，仅打包 exe 时需要（`python scripts/main_build.py`。旧 `build.py` 已重导向到 `main_build.py`） |

```powershell
pip install -e ".[dev,build]"   # 开发 + 打包一次装齐
```

> **venv 编码损坏**：如果 `pip install` 后报 `SyntaxError: invalid character`（如 `㈠ (U+3220)`），说明 venv 的 site-packages 被 GBK 编码损坏。详见 [`docs/agents/encoding-corruption-handling.md`](agents/encoding-corruption-handling.md) §6。

### 1.5 提交签名（必需，GitHub Verified）

要想 GitHub Release 显示 **Verified** 标记，必须：

**第一步**：将 SSH 公钥添加到 GitHub
1. 打开 GitHub → Settings → SSH and GPG keys → **Signing keys**
2. 点击「New Signing Key」，粘贴你的 SSH 公钥内容（如 `id_ed25519.pub`）

**第二步**：本机配置 Git

```powershell
git config --global gpg.format ssh
git config --global user.signingkey C:/Users/你的用户名/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
```

**第三步**：验证配置

```powershell
echo "test" | git tag --verify -s test-sign-verify 2>&1; git tag -d test-sign-verify
```

| 作用 | 说明 |
|------|------|
| 上传脚本 | 自动检测签名配置。commit 由 `commit.gpgsign` 自动签名；**tag 由脚本带 `-s` 显式签名**（2026-05-30 修复） |
| GitHub Verified | 签名后的 tag 推送后，GitHub Release 页面显示 ✅ **Verified** 绿色标记 |
| 未配置 | 脚本会打印设置提示；commit 和 tag 仍可进行，但 GitHub 不显示 **Verified** |
| 历史提交 | 旧 commit/tag 不会补签 |

### 2.2 全量遍历 / MVP 搜索（实验）

界面在 **高级页**「全量搜索」「多技能次数」区（原底栏三列已迁入页签）。详见 [`docs/MVP搜索验收说明.md`](MVP搜索验收说明.md)。

| 操作 | 说明 |
|------|------|
| 全量遍历 | `全量遍历(弹窗结果)` → 弹窗 TopN；写入 **`[包]/search_output/full_search_*`** 或 **exe 同级 `search_output/`** |
| 评分方式 | 默认：左侧当前技能**单段伤害**；开「使用手动次数」：**Σ(各技能单段×次数)** |
| 固定配装 | 勾选 0–4 件具体装备；未勾选部位在装备范围内遍历 |
| MVP 导出 | `实验：MVP搜索并导出` → 默认打开 `search_output/`；取消则自动建子目录 |
| 并行线程 | **自动 = 1 worker**（Rust job 批量默认）；说明区显示本机物理核心/逻辑线程；手动选项在批量路径下仍有效为 1；实验多 worker 设 `CALC_SEARCH_BATCH_POOL=1` |
| 预计耗时 | 组合约 ≥2 分钟会确认；97 万组合单 worker 约 1 分钟量级（视 CPU/配置） |
| 取消 | 遍历中点「取消搜索」 |
| 装备数据 | 需 `equipments.json` 三部位非空；可先 `sync_equipments.py --apply` |

**frozen 搜索环境变量**（exe 诊断/实验，见 [`docs/错误集.md`](错误集.md)）：

| 变量 | 默认 | 说明 |
|------|------|------|
| `CALC_FROZEN_SEARCH_PHASE` | `3` | 分阶段恢复 0–5；3 = QThread + job 批量 + 单 worker |
| `CALC_SEARCH_BATCH_POOL` | 关 | `=1` 实验 batch ThreadPool 多 worker（通常更慢） |
| `RUST_SEARCH_FALLBACK` | 关 | `=1` 强制纯 Python 搜索 |
| `CALC_SEARCH_LOG_LEVEL` | frozen=DEBUG | 写入 `<exe>/logs/search.log` |

开发时 `search_output/` 在 `[包]` 下，已列入 `.gitignore`，可整夹删除。

## 3. 改游戏数据（角色 / 武器）

### 3.1 数据文件位置

| 数据 | 路径 |
|------|------|
| 角色 | `[包]/data/characters.json` |
| 武器 | `[包]/data/weapons.json` |

## 5. GitHub 上传与下载（`[根]`）

### 5.1 上传（推荐日常用这个）

```powershell
cd calc-framework   # [根]
python github_upload_module.py --check      # 仅自检，不 commit/push
python github_upload_module.py --dry-run    # 预览模式：展示变更与版本计划，不实际修改
python github_upload_module.py
python github_upload_module.py --minor      # 第二位 +1：新武器/新乘区等
python github_upload_module.py --no-bump    # 提交推送但不改 _VERSION（commit 失败/补推时用）
python github_upload_module.py --tag        # 上传成功后推送 git 标签，触发 CI 自动构建「已验证」发行版
python github_upload_module.py --minor --tag  # 组合使用
python github_upload_module.py --minor --no-git-backup  # 跳过本地 .git 备份（不推荐）
```

> **排障与 pre-commit 两轮机制**：见 [`docs/上传脚本与-pre-commit.md`](上传脚本与-pre-commit.md)（**必读**）。
> 常见：`ruff-format` 第 1 轮 Failed 正常；`ruff-lint` 行 Failed 须手修；**`F822 SUMMARY_END`** → 查 `scripts/_version.py` 顶部两行；**目录重构后旧文件 ` D`** → 脚本已自动 `git add -u`（§6.3），遗留可手动 `git add -u web/backend/api/`；中文 doc 路径勿对 porcelain 用 `Path()`。bump 成功但 commit 失败 → **`--no-bump`**。

| 步骤 | 作用 |
|------|------|
| 检测业务改动 | 仅有 `scripts/_version.py` / `scripts/please_read_me.py` / 包内 `please_read_me.py` 改动时不 bump |
| 交互 P/M | 回车 = patch（第三位 +1）；输入 `M` = minor |
| 写总结块 | 在 `_version.py` **底部**生成 `# --- UPLOAD_SUMMARY ---` |
| commit | 消息形如 `v3.11.21: 标题` + 改动列表（读总结块） |
| 提交签名 | 若本机已配置 `commit.gpgsign` 或 `user.signingkey`，脚本自动签名（后者用 `git commit -S`）；未配置会提示如何设置，以便 GitHub 显示 **Verified** |
| `--tag` | push 成功后将 `v{_EXE_VERSION}` 标签推到 GitHub（如 `v0.6.0-beta`），自动触发 CI 构建 exe 并创建「已验证」发行版（见下文 §5.4） |
| **Minor 备份** | `--minor` 或交互 **M** 时，commit 前自动复制 `.git` → `git_backup/snapshots/`（见 [`git_backup/README.md`](../git_backup/README.md)） |
| pre-commit | 提交前对**暂存路径**跑 hook，最多 2 轮；第 1 轮 format/换行 Failed 可自愈，`ruff-lint` Failed 须手修 |
| `--check` | 上传前自检（rebase/merge/断历史），不 bump/commit/push |
| push 成功 | 删除底部总结块；**失败则自动回滚 `_VERSION`**，本地 commit 保留 |
| push 失败 | 自动回滚 `_VERSION` 到推送前值；修复后 `--no-bump` 补推 |
| 纯补推 | 仅有未 push 的 commit、无新改动 → **不** bump、不写总结 |

**不要**用裸 `git commit` + `git push` 代替上传脚本，否则 `_VERSION` 可能与远程不同步。

> **⚠️ stash pop 超时处理**：上传脚本内部执行 `stash push → pull → stash pop`。如果暂存区包含大量新文件（如 `tools/arknights_scout/output/parsed/operators.json` 78K 行），`stash pop` 可能超时（30s）。此时：
> 1. 暂存区文件不受影响（`git add` 后的文件在 stash 前就已入索引）
> 2. 残留 stash 可用 `git stash drop 'stash@{0}'` 清理
> 3. 绕过脚本，**直接手动提交+推送**：`git commit -m "消息" && git push origin main`

### 5.2 从远程覆盖本地（危险）

| 39 MB zip 上传慢 | PythonAnywhere Files API 逐文件上传大文件耗时长 | 或考虑上传压缩后解压（暂不优化） |

### 7.1 编码完整性扫描

对所有文本文件进行 UTF-8 解码完整性检查（排除 `node_modules/`、`.venv/`、`.git/`）：

```powershell
cd e:\endfield_damage_calculator   # [根]
python -c "
import glob, os, ast, json
SKIP = {'dist','node_modules','.venv','.git','__pycache__'}
EXTS = {'*.py','*.pyw','*.json','*.md','*.html','*.xml','*.yml','*.yaml',
        '*.ts','*.tsx','*.js','*.css','*.sh','*.bat','*.ps1','*.toml',
        '*.spec','*.nsi','*.gitignore','*.cfg','*.conf','*.ini','*.txt',
        '*.mdc','*.cursorrules'}
fail = False
for e in EXTS:
    for f in glob.glob(f'**/{e}', recursive=True):
        p = os.path.normpath(f).split(os.sep)
        if any(s in p for s in SKIP) or not os.path.getsize(f):
            continue
        try:
            src = open(f,'r',encoding='utf-8').read()
        except UnicodeDecodeError:
            print(f'DECODE_FAIL: {f}'); fail = True; continue
        if f.endswith('.py') or f.endswith('.pyw'):
            try:
                ast.parse(src)
            except SyntaxError as e:
                print(f'SYNTAX_ERROR: {f}: {e}'); fail = True
        elif f.endswith('.json'):
            try:
                json.loads(src)
            except json.JSONDecodeError as e:
                print(f'JSON_ERROR: {f}: {e}'); fail = True
if not fail: print('所有文本文件检查通过')
"
```

> 编码损坏常见于 Windows GBK 环境下创建/修改文件。详见 [`docs/agents/encoding-corruption-handling.md`](agents/encoding-corruption-handling.md)。

## 11. BWIKI 数据侦察与同步 + Wiki 通用爬虫（`[根]` + `[工具]`）

对比 [终末地 BWIKI](https://wiki.biligame.com/zmd/) 与本地 JSON。侦察与草案解析**默认不写**正式数据；经 `sync_*.py --apply` 才写入（以 Wiki 为准）。

### 11.0 通用 Wiki 爬虫框架

`tools/wiki_scout/` 是通用 MediaWiki 客户端，支持任意 MediaWiki 平台的 Wiki 数据抓取：

| 文件 | 说明 |
|------|------|
| `client.py` | 通用 MediaWiki 客户端：`call()` / `query_category()` / `get_page_text()` / `get_page_html()` / `search()` / `get_page_info()` |
| `extractor.py` | 数据提取基类 `BaseExtractor` + `ExtractedData` 数据类 |
| `providers/bwiki.py` | BWIKI 平台适配器，继承 BaseExtractor |

```python
from tools.wiki_scout import MediaWikiClient, detect_wiki_type, get_api_url

client = MediaWikiClient("https://wiki.biligame.com/zmd/api.php")
pages = client.query_category("角色")
text = client.get_page_text("陈千语")
```

### 11.1 拉取缓存与对照

```powershell
cd e:\calc-framework   # [根]
python tools/bwiki_scout/scout.py
python tools/bwiki_scout/scout.py --limit 5    # 调试：每类限量
python tools/bwiki_scout/parse_draft.py
python tools/bwiki_scout/compare_stats.py      # 仅离线重算报告
```

| 路径 | 说明 |
|------|------|
| `tools/bwiki_scout/output/` | **本地持久缓存**（`raw/` 每页 `wikitext.txt`、`html.html`；gitignore；续跑跳过已有页） |
| `output/parsed/*.json` | 阶段 B 草案，仅供对照 |
| `output/reports/stats_diff.md` | 干员 1–90 级对比（`干员名/详细数据` wikitext） |
| [`tools/bwiki_scout/README.md`](../tools/bwiki_scout/README.md) | 模块说明、Wiki→本地字段映射 |
| [`tools/bwiki_scout/CACHE.md`](../tools/bwiki_scout/CACHE.md) | 缓存续跑与备份 |

`scout.py` 会为每名干员额外拉取 **`干员名/详细数据`** 子页。

### 11.2 Wiki 数据来源（同步时）

| 本地字段 | Wiki 来源 |
|----------|-----------|
| 干员四维、基础攻击力（90 级） | `raw/<干员>/详细数据/wikitext.txt`（模板 `干员/逐级等级`） |
| 战技 / 连携 / 终结技倍率 | `raw/<干员>/html.html` 技能区各 tab 的「伤害倍率」行（12 级） |
| 武器基础攻击力（90 级） | `raw/<武器>/wikitext.txt` 的 `基础攻击力`、`满级基础攻击力` |
| 武器附加属性、特殊能力 | 同页 `词条1rank1–9`、`词条2rank…`、`词条3副1rank…`（须含完整成长块） |
| 装备部位/套装/效果文本 | `output/parsed/equipment.json`（`parse_draft.py` 生成） |

无 `词条1rank1` 等字段的武器页（如部分低星 Wiki 简表）会被 `sync_weapons.py` 跳过。

### 11.3 同步到本地 JSON / seed（预览 → 写入）

```powershell
# 干员：characters.json + games/endfield/scripts/seed_characters.py
python tools/bwiki_scout/sync_operators.py
python tools/bwiki_scout/sync_operators.py --apply
python tools/bwiki_scout/sync_operators.py --apply --only 秋栗 佩丽卡
python tools/bwiki_scout/sync_operators.py --new          # 导入本地尚无的新干员（须先 scout）

# 武器：weapons.json + scripts/seed_weapons.py（仅 Wiki 含 rank 成长块者）
python tools/bwiki_scout/sync_weapons.py
python tools/bwiki_scout/sync_weapons.py --apply
python tools/bwiki_scout/sync_weapons.py --new              # 预览可导入的新武器
python tools/bwiki_scout/sync_weapons.py --new --apply      # 写入新武器 + 更新 seed

# 装备：data/equipments.json（基于 parsed/equipment.json）
python tools/bwiki_scout/sync_equipments.py
python tools/bwiki_scout/sync_equipments.py --apply

# 一键：干员 + 武器 + 装备（默认增量同步）
python tools/bwiki_scout/sync_all.py
python tools/bwiki_scout/sync_all.py --apply
python tools/bwiki_scout/sync_all.py --apply --new
python tools/bwiki_scout/sync_all.py --apply --full                 # 全量同步
python tools/bwiki_scout/sync_all.py --apply --bump-version        # 写入后自动 bump 数据版本
python tools/bwiki_scout/sync_all.py --apply --bump-version --verify  # 写入+bump+验证测试
```

> **注意**：BWIKI 会将所有装备（包括无套装效果的散件）赋予 `所属套组` 字段。同步工具在写入 `套装` 字段时会自动检测装备的套装效果（`效果` + `三件套效果`），如果两者均为空则不视为套装装备，保持 `套装` 字段为空。GUI 中「仅散件装备」过滤器基于此逻辑正确区分套装与散件。

反推使用包内 `calculation.inverse`（与手动 seed 录入同一套公式）。须遵守 Wiki 条款与 [`DATA_LICENSE`](../DATA_LICENSE)；**商用不可用**本仓库数据或侦察/同步流程产出。
