# 代码结构规范

> **约束来源**：[ADR-0001：代码目录与文件规模约束](adr/0001-code-layout-constraints.md)  
> **受众**：维护者、贡献者、Cursor Agent（新代码与重构均须遵守）

---

## 1. 两条铁律

### 1.1 目录宽度

- 任意目录下 **直接子项（文件 + 文件夹）≤ 10**。
- **数子项时包括**：`.py`、子文件夹、`README.md` 等；**不包括** `__pycache__`、`.pytest_cache`。
- 第 11 个子项出现前，必须先建子目录并迁入，或合并相关文件。

### 1.2 文件长度

- **目标**：单个 `.py` **≤ 400 行**（可读、可测、可 review）。
- **硬顶**：业务/GUI/计算代码 **> 500 行不得新增**；已有超长文件列入迁移 backlog，拆分时优先动刀。
- **例外申请**：须在 PR 或 Issue 说明理由，并更新 ADR 或本文件 §5 豁免表。

---

## 2. 放什么、不放什么

| 位置 | 放 | 不放 |
|------|----|------|
| `calculation/` | 伤害链、搜索、配装优化、与 GUI 无关的纯逻辑 | CustomTkinter、文件对话框 |
| `gui_design/` | CTk 布局、事件、展示；按 `presentation` / `app` / `panels` / `controls` / `shell` 分子包 | 直接读 JSON 文件（走 `data/`） |
| `data/` | loader、facade、catalog | 伤害公式 |
| `tests/` | 与生产**同构**的子目录 + `conftest.py` / 共享 fixture | 与生产无关的「杂物测试」堆根目录 |
| `scripts/` | 录入、seed、本地 CLI | 被 GUI 导入的运行时代码 |
| `tools/`（仓库根） | BWIKI、上传、审计 | 包内 import 的模块 |

---

## 3. 命名与拆分手法

1. **先按领域拆目录**，再按职责拆文件（与「一个文件夹里堆 20 个 utils」相反）。
2. 单类过大：用 **mixin** 或 **按 UI 区块拆模块**（本项目 `gui_design/shell/app_*.py` 为范例）。
3. 纯函数集合：独立 `*_lines.py` / `*_helpers.py`，由薄 `__init__.py` 或聚合模块 re-export。
4. **Import（方案 B）**：根路径 stub 已移除；**新代码禁止** `from gui_design.loadout_state` 等旧路径。
5. 注释语言：**中文**（与仓库约定一致）。

## 6. Agent / PR 自检清单
