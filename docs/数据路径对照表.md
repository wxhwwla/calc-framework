# 数据路径对照表

> 创建：2026-06-17（Phase 4 Step 4.1）  
> 对应：ADR-0023 / 缺陷报告 **M13**  
> 实施计划：[`docs/plans/phase-4-ecosystem-plan.md`](plans/phase-4-ecosystem-plan.md)

本文档是仓库内**游戏 JSON 与适配器数据**的单一事实来源。修改加载逻辑或部署脚本前请先对照本表。

---

## 1. 四层模型

| 层级 | 含义 | 是否入 Git | 典型用途 |
|------|------|:----------:|----------|
| **A. 运行时主数据** | 游戏包内权威 JSON， deps 直接读取 | 是（终末地）/ 视 scout | 桌面 GUI、DAG loader |
| **B. 适配器快照** | `framework/adapters/{game}/data/` 下 `*_standard.json` | 是 | Web profile、设计器、打包回退 |
| **C. Scout 产出** | `tools/*/output/` 解析/对比结果 | **否**（gitignore） | 维护者同步、明日方舟 parsed |
| **D. 发布/部署 COPY** | Docker、PythonAnywhere、PyInstaller 打包路径 | 构建时生成 | 生产环境 |

**当前不一致点（M13）**：终末地运行时主数据在 **A=`games/endfield/data/`**；明日方舟运行时主数据在 **C=`tools/arknights_scout/output/parsed/`**（或 zip），回退 **B=`framework/adapters/arknights/data/operators_standard.json`**。Step 4.3 将分步对齐，本表先固定现状。

---

## 2. 终末地（endfield）

### 2.1 运行时主数据（层 A — 权威源）

| 文件 | 路径 | 加载入口 |
|------|------|----------|
| 角色 | `games/endfield/data/characters.json` | `games/endfield/data_loading/loader.py` → `CHARACTERS_JSON_PATH` |
| 武器 | `games/endfield/data/weapons.json` | `WEAPONS_JSON_PATH` |
| 装备 | `games/endfield/data/equipments.json` | `EQUIPMENTS_JSON_PATH` |
| 数据版本 | `games/endfield/data/data_version.json` | `tools/bwiki_scout/bump_data_version.py` |

子目录（如 `weapon_data/`）为历史/专项 JSON，以 loader 与 sync 脚本引用为准。

### 2.2 适配器快照（层 B）

| 文件 | 路径 | 用途 |
|------|------|------|
| 角色标准库 | `framework/adapters/endfield/data/characters_standard.json` | Web `DataProfile`、设计器 entity 表 |
| 武器标准库 | `framework/adapters/endfield/data/weapons_standard.json` | 同上 |
| 装备标准库 | `framework/adapters/endfield/data/equipments_standard.json` | 同上 |

`tools/designer/data_editor/profiles.py` 中 `endfield` profile 的 `adapter_dir` 指向 `framework/adapters/endfield`，entity 表读取 **B 层** 文件。

### 2.3 Scout（层 C）

| 路径 | 说明 |
|------|------|
| `tools/bwiki_scout/output/` | BWIKI 对比/预览，**不入库** |
| `tools/bwiki_scout/sync_*.py` | `--apply` 时写入 **层 A** `games/endfield/data/` |

### 2.4 打包与部署（层 D）

| 场景 | 路径策略 |
|------|----------|
| PyInstaller | `scripts/main_build.py` 捆绑 `games/endfield/data` → `games/endfield/data` |
| Docker | `Dockerfile` COPY 仓库内 A 层 |
| PythonAnywhere | `web/scripts/deploy_pythonanywhere.py` → `_upload_game_data()` 上传 `games/endfield/data/` |

## 3. 明日方舟（arknights）

### 3.1 运行时主数据（层 A — 现状分散）

明日方舟**没有** `games/arknights/data/` 目录。运行时按优先级合并：

| 优先级 | 路径 | 常量 / 函数 |
|:------:|------|-------------|
| 1 | `tools/arknights_scout/output/parsed/*.json` | `operator_catalog.default_parsed_dir()` |
| 2 | exe 同级 / 仓库根 `arknights_parsed.zip` | `default_zip_candidates()` |
| 3 | `framework/adapters/arknights/data/operators_standard.json` | `STANDARD_OPERATORS_REL`（≥100 条回退） |

加载入口：`games/arknights/operator_catalog.py` → `load_operators_map()`。

**阈值**：`MIN_PARSED_COUNT = 100`；parsed 目录不足时自动合并 zip 与标准库。

### 3.2 适配器快照（层 B）

| 文件 | 路径 | 用途 |
|------|------|------|
| 干员标准库 | `framework/adapters/arknights/data/operators_standard.json` | 打包无 scout 数据时的回退；人工验收「≥418 干员」指此库或完整 parsed |
| 设计器引用名 | `operators.json`（**逻辑名**，见 profiles） | `tools/designer/data_editor/profiles.py` → `ARKNIGHTS_OPERATORS_JSON` 实际指向 **parsed/operators.json** |

### 3.3 Scout（层 C）

| 路径 | 说明 |
|------|------|
| `tools/arknights_scout/output/parsed/` | BWIKI 解析干员 JSON，**默认不入 Git** |
| `tools/compact_arknights_operators` 等 | 压缩/整理 parsed → zip |

### 3.4 Web API（层 D）

| 组件 | 路径 |
|------|------|
| 路由 | `web/backend/api/arknights.py` |
| 适配器根 | `api/internal/json_utils.ADAPTER_ROOT` → `framework/adapters/` |
| 计算 | `games/arknights/calc/dag_adapter.compute_snapshot_with_dag` |
| 部署 COPY | `deploy_pythonanywhere.py` 上传 `framework/adapters/arknights` |

Web 与桌面共用 `load_operators_map()`；500 错误文案提示放置 parsed 或 zip。

## 4. 框架适配器（非 JSON 数据）

| 游戏 | 目录 | 内容 |
|------|------|------|
| endfield | `framework/adapters/endfield/` | `functions.py`、`ui/layout.json`、`meta.json` |
| arknights | `framework/adapters/arknights/` | 同上 + `data/operators_standard.json` |
| 演示 | `framework/adapters/card_rpg/`、`genshin_like/` | 演示用 JSON + README |

DAG 公式**只**在 `functions.py`；JSON 仅属性/实体数据。

## 5. 路径解析工具

| 函数 | 模块 | 行为 |
|------|------|------|
| `get_resource_path(rel)` | `utils/path_utils.py` | 开发=仓库根；PyInstaller=`sys._MEIPASS` |
| `get_application_dir()` | 同上 | exe 所在目录（用户数据、zip 候选） |
| `REPO_ROOT` | 各模块自行 `Path(__file__).parents[N]` | **勿**假设统一 depth；Web `api/internal/json_utils.py` 为 `parents[4]` |

## 6. ADR-0023 目标态与同步工具（Step 4.3 ✅）

| 游戏 | 层 A 权威源 | 层 B 快照 | 同步命令 |
|------|-------------|-----------|----------|
| endfield | `games/endfield/data/*.json` | `framework/adapters/endfield/data/*_standard.json` | `python tools/sync_adapter_snapshots.py --game endfield --apply` |
| arknights | `tools/arknights_scout/output/parsed/` | `framework/adapters/arknights/data/operators_standard.json` | `compact --write-standard` 或 `sync_adapter_snapshots --game arknights --apply` |

**路径常量模块**：`utils/game_data_paths.py`（loader、operator_catalog、profiles 共用）。

**遗留**：`games/arknights/data/` 不再作为 standard 输出目标（旧 pipeline 已修正）；运行时仍无 `games/arknights/data/` 层 A 目录。

## 7. 修改检查清单

变更任一路径时逐项确认：

- [ ] 本表已更新
- [ ] `games/*/data_loading` 或 `operator_catalog.py` 常量
- [ ] `tools/designer/data_editor/profiles.py` 的 `data_dir_for_profile`
- [ ] `scripts/main_build.py` / `Dockerfile` / `deploy_pythonanywhere.py`
- [ ] `web/backend/api/entity/profiles.py`（若影响 Web CRUD 根路径）
- [ ] 相关 pytest（`@pytest.mark.real_data`）
- [ ] [`docs/数据来源与许可.md`](数据来源与许可.md) 路径索引
