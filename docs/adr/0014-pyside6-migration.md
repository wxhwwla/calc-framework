# ADR-0014：GUI 框架从 CustomTkinter 迁移到 PySide6

**日期**：2026-05-26  
**状态**：已批准  
**影响范围**：`gui_design/` 目录全部 87 个 `.py` 文件，约 10,680 行代码

---

## 背景

当前 GUI 基于 CustomTkinter（CTk）搭建。运行中暴露三个影响用户体验的核心问题：

1. **主线程计算卡顿** — 耗时计算直接运行在 tkinter 的 `mainloop` 线程中，导致界面冻结，用户无法拖动/缩小/交互
2. **页面切换撕裂** — 使用 `grid_forget`/`pack_forget` 刷新属性显示时，肉眼可见闪烁
3. **控件文字截断** — CTk 控件使用固定像素宽度，超出部分直接截断，无法自适应

## 方案选择

分析了三条迁移路径，最终选择 **路径 1：双后端 + 编译期切换**：

| 方案 | 描述 | 选中 |
|------|------|:----:|
| Big Bang 重写 | 停止开发，一口气重写全部 | ❌（风险高、无回滚） |
| 抽象 UI 接口层 | 定义工厂接口，两套后端 adapter | ✅ **选中** |
| Strangler Fig 子进程 | IPC 通信隔离两套 UI | ❌（复杂度与项目规模不匹配） |

## 决策

1. 采用 **超薄 adapter + factory 模式**，不定义厚抽象层
2. 文件按 **平行目录** 布局，PySide6 实现以 `qt_` 前缀命名
3. 运行时通过环境变量 `ENDFIELD_UI_BACKEND` 切换（`"ctk"` / `"qt"`）
4. 首次迁移目标：**高级页控制栏**（`app_control_dock.py`，~122 行，风险最低）
5. 迁移期间两套实现共存，CTk 为**默认后端**，最终阶段切换默认

## 迁移计划

预计 14 天完成 6 个阶段：

| 阶段 | 天数 | 内容 |
|------|------|------|
| 0 基础设施 | 1-2 | 双后端骨架 + 切换机制 |
| 1 控制栏 | 3-5 | 高级页控制栏首迁移 |
| 2 线程分离 | 5-7 | QThread + Worker |
| 3 显示三列 | 7-9 | 属性区域重写 |
| 4 选择面板 | 9-11 | 角色/武器选择器 |
| 5 剩余模块 | 11-13 | 按优先级填充 |
| 6 收尾 | 14 | 切换默认 + 回测 |

## 回滚

- 阶段内：设 `ENDFIELD_UI_BACKEND=ctk` 即可
- 彻底：`git checkout -- gui_design/` 删除所有 `qt_*.py`
- 增量：删问题文件，修改对应 `__init__.py`

## 影响

- `pyproject.toml` 新增 `[qt]` optional dependency
- `gui_design/` 目录代码量临时翻倍（迁移期间）
- 最终阶段删除 CTk 代码后可减少回 ~5,000 行
- 打包策略：PyInstaller 需增加 `--collect-all PySide6`
