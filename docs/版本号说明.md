# 版本号说明

> 定义本仓库中的版本号分类、管理方式和各组件当前版本。

---

## 1. 版本号分类

本仓库有两类版本号：

| 类型 | 常量名 | 管理方式 | 用途 |
|------|--------|----------|------|
| **项目版本** | `_VERSION` | 上传脚本自动 bump | 仓库全局版本、pip 包版本 |
| **组件版本** | 各组件自定义 | 手动修改 | 各 GUI/应用的发布版本 |

两类版本号**彼此独立**。项目版本由上传脚本在每次 push 时自动递增第三位（`--minor` 递增第二位），组件版本由维护者在打包/发布前手动更新。

---

## 2. 项目版本号

| 文件 | 当前值 |
|------|--------|
| `scripts/_version.py` | `_VERSION = "3.24.6"`（唯一源头） |
| `scripts/please_read_me.py` | 从 `scripts/_version.py` 导入 `_VERSION` |
| `games/endfield/please_read_me.py` | 从 `scripts/_version.py` 导入 `_VERSION` |

**说明**：`_VERSION` 唯一定义在 `scripts/_version.py`，其余文件均通过 import 读取，不再维护独立拷贝。上传脚本在有「业务改动」并 push 成功时自动递增（默认第三位 +1）。

**自动 bump 规则**（由 `github_upload_module.py` 执行）：
- 默认：第三位 +1（如 `3.24.6 → 3.24.7`）
- `--minor`：第二位 +1，第三位归零（如 `3.24.6 → 3.25.0`）
- `--no-bump`：不修改

### 3.3 管理规则

- **组件版本由维护者手动修改**，不上传脚本自动 bump
- **Web 版与桌面 GUI 共享同一套版本号**——同一个组件的 web 和 gui 版本一致
- **更新流程**：修改某个组件时 → 同时更新该组件版本号 + 项目版本号（上传脚本自动处理后者）
- 当前无独立版本常量的组件，后续若需正式发布可为其添加 `_XXX_VERSION` 常量

### 3.4 初始化基线

所有新组件（包括已有但未设版本号的）初始版本为 `0.1.0`，表示：
- 第一位 `0`：正式版尚未发布（按语义化版本规定）
- 第二位 `1`：有实质性可用功能
- 第三位省略（`0.1.x` 模式）：仅一位小数，补丁不体现
