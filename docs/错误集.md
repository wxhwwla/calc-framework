## `_SUMMARY_MARKER_END` 回归：线上 CI 全挂（2026-07-30，已修复）

**问题**：`v3.29.13` 推送后 Game CI / Web CI backend / Type Check / Web E2E / pip-audit 全部失败；本地此前 act 绿。

**现象**：
- Game CI lint：`F821 Undefined name '_SUMMARY_MARKER_END'`
- 其余流水线：`pip install -e games/endfield` → `NameError: _SUMMARY_MARKER_END is not defined`

**根因**：
1. `_canonical_marker_header()` 再次只写 `_SUMMARY_MARKER_BEGIN = ""`，**不写** `_SUMMARY_MARKER_END = ...` 定义行
2. `_markers_section_ok()` 自相矛盾（既要求 `BEGIN = ""`，又要求不能有空字符串），导致上传脚本每次 `ensure_summary_marker_assignments()` 都用坏掉的 canonical 头覆盖磁盘文件
3. 因此「本地 act 绿 → 上传脚本改写 `_version.py` → 线上挂」

**修复**：
- 模块级标记恢复为非空：`"# --- BEGIN/END UPLOAD_SUMMARY ---"`
- `_canonical_marker_header()` 同时写出 BEGIN + END 定义
- `_markers_section_ok()` 精确匹配非空字面量

**涉及文件**：`scripts/_version.py`

**状态**：✅ 已修复（待重新上传验证线上）

## 2026-07-22 CI 容器化测试修复

### CI-1. arknights 测试失败被静默吞掉（已修复）

**问题**：`ci.yml` 第 120 行 `|| echo "ARKNIGHTS_TESTS_SKIPPED"` 导致 arknights 测试失败时 CI 仍然通过。

**原因**：原设计是 arknights 测试可选，但实际有 8 个测试失败（导入路径错误、数据格式不匹配等）被隐藏。

**修复**：移除 `|| echo`，修复所有 8 个失败测试（导入路径、数据物化、认证 header）。

### CI-2. 测试数据未物化导致 0 伤害（已修复）

**问题**：`_load_by_name()` 直接读取 compact JSON（`成长参数` 未展开），导致 DAG 计算返回 0 伤害。

**原因**：数据已被 compact 化（`成长参数` 包含成长曲线参数），但测试直接读原始 JSON 而非物化后的数据。

**修复**：8 个测试文件的 `_load_by_name` 函数添加 `materialize_character_entity` / `materialize_weapon_entity`。`conftest.py` 的 `load_character_by_name` / `load_weapon_by_name` 同步修改。

### CI-3. `_version.py` 标记变量为空字符串（已修复）

**问题**：`_SUMMARY_MARKER_BEGIN` 和 `_SUMMARY_MARKER_END` 初始化为 `""`，导致 `write_summary_block` / `read_summary_for_commit` / `strip_summary_block` 全部失效。

**原因**：`_canonical_marker_header()` 写入空字符串，`_markers_section_ok()` 又要求非空，形成矛盾。

**修复**：将标记值从 `""` 改为 `"# --- BEGIN UPLOAD_SUMMARY ---"` / `"# --- END UPLOAD_SUMMARY ---"`（Python 注释格式），同步更新 `_canonical_marker_header` 和 `_markers_section_ok`。并在 `.pre-commit-config.yaml` 中排除 `_version.py` 避免 ruff 反复删除标记行。

### CI-4. CPU 核数测试依赖宿主机（已修复）

**问题**：`test_search_settings.py` 的 `test_with_explicit_count` 断言 `physical_cores == 8`，但 `_detect_physical_cores` 使用全局缓存，在 CI 容器（8 核）和本地（24 核）返回不同值。

**修复**：使用 `monkeypatch.setenv("CALC_PHYSICAL_CORES", "8")` + 清除 `_physical_cores_cache`，确保测试隔离。

### CI-5. Hub API 测试缺少认证（已修复）

**问题**：Hub 测试返回 401（未认证），因为 `verify_admin_token` 要求 `X-Admin-Token` header。

**修复**：`TestHubUploadAndDownload` 和 `TestHubListEndpoint` 添加 `setUp` 设置 `CALC_ADMIN_TOKEN` 环境变量 + 请求 header。

### M3. DAG 图编辑器输入框焦点丢失（已修复）

**问题**：在属性面板中编辑节点"名称"或"变量路径"时，每输入一个字符就会失去焦点，需要重新选中才能继续输入。

**原因**：`_on_node_config_changed()` 函数中调用了 `prop_panel.show_node(ni.to_graph_node())`，这会重建整个表单，导致输入框被销毁并重新创建。

2. `_on_label_changed` 或 `_on_path_changed` 触发
3. `node_changed.emit` 发出信号
4. `_on_node_config_changed` 被调用
5. `prop_panel.show_node()` 重建表单
6. 输入框被销毁并重新创建，失去焦点

**修复**：移除 `_on_node_config_changed` 中的 `show_node()` 调用，只保留画布节点更新和预览值更新。

**涉及文件**：
- `framework/src/calc_framework/graph_editor/__main__.py`

**状态**：✅ 已修复

### PyInstaller exe 全量遍历崩溃

**问题**：打包后的 `Game Calc Platform.exe` 启动全量装备遍历时进程闪退或无响应；开发模式 `python games/endfield/main.py` 正常。

**原因**：
1. 全量搜索默认 `parallel_backend=auto`，`max_workers>1` 时使用 `ProcessPoolExecutor`
2. Windows + PyInstaller onefile：`spawn` 会反复启动整个 exe 解压包，与 PySide6 / Rust `rust_search.pyd` 冲突，易 segfault
3. 批量路径曾误在 `parallel_backend=thread` 时仍走多进程；续跑 `(key, task)` 元组未剥离就送入进程 batch worker，异常被 `_run_parallel_loop` 吞掉导致 `processed=0`

**修复**（2026-06-16）：
1. `parallel.py`：`sys.frozen` 时强制 `thread` 后端（单进程线程池 + Rust 批量，不再 spawn 子 exe）
2. `parallel.py`：批量路径按已解析的 `backend` 选线程/进程，不再仅因 `process_payload` 存在就 ProcessPool
3. `process_worker.py`：新增 `evaluate_optimizer_batch_keyed_in_process` 剥离 combo key
4. `persist/store.py`：续跑仅在 `total_combinations > batch_size` 时启用批量
5. `launcher_entry.py` / `games/endfield/main.py`：`multiprocessing.freeze_support()` 提前到 `__main__` / `main()` 入口
6. `main_build.py`：`hidden-import rust_search` + `collect-submodules extensions.rust_search`
7. `utils/search_diagnostics.py`：统一写入 exe 旁 `logs/`（`search.log` / `crash.log` / `app.log`），GUI 搜索线程与并行循环记录进度与异常

**续查修复**（2026-06-16，崩溃仍发生时）：
1. `persist/store.py` / `in_memory_optimizer.py`：GUI 传入 `search_job` 时改用 `make_loadout_task_evaluator`，**不再**对续跑项误走 `evaluate_task_batch`
2. `parallel.py`：`sys.frozen` 时 `_resolve_max_workers()` 强制为 **1**
3. `optimizer/evaluate.py`：`_loadout_cache` 加 `threading.Lock`
4. `rust_bridge.py`：Rust FFI 调用加全局锁

**深层修复**（2026-06-16，仍崩溃）：
1. **Qt 跨线程信号**：`SearchWorker` 在 QThread，但 `ThreadPoolExecutor` 回调里 `progress.emit()` → PySide6 随机崩溃；`sys.frozen` 时改 `_run_inline_loop` 在调用线程顺序执行（`executor=inline`）
2. **PyInstaller + rust_search.pyd**：frozen 启动时默认 `RUST_SEARCH_FALLBACK=1`（`launcher_entry.py` / `games/endfield/main.py`，须在 `rust_bridge` 导入前）
3. `endfield_search.py`：搜索信号显式 `QueuedConnection`

**第四轮**（仍崩溃 — 最激进路径）：
1. **`endfield_search.py`**：frozen 下**不用 QThread**，主线程同步跑 `SearchWorker.run()` + `processEvents()` 泵进度（彻底消除 Qt 跨线程）
2. **`utils/frozen_runtime.py`**：frozen 恒 `use_rust_search_accel()=False`；`evaluate.py` **不再 import rust_bridge**
3. **`spawn_detached`**：子进程继承 `RUST_SEARCH_FALLBACK=1`
4. **`qt_actions.py`**：修复未赋值 `_workers_choice` 导致日志/潜在异常
5. 内联循环每 1000 条写 `内联心跳` 到 search.log（判断崩溃点）

**Phase 3 多 worker batch 实测更慢**（2026-06-16）：Rust job 批量摊销 FFI 后，瓶颈转为 Python 预处理 + GIL + `_loadout_cache` 锁；多 batch worker 实测 97w **~1.5min**，单 worker **~1min**。**默认**：「自动」= **1 worker**、内联 batch（`batch_pool=off`）；GUI 选手动大线程数也会被压成 1。实验多 worker：`CALC_SEARCH_BATCH_POOL=1`（可选 `CALC_RUST_PARALLEL_BATCH=1`）。

## 合并分支与 CRLF 处理（2026-06-19）

**问题**：`--minor` 上传后合并 develop → main 时，`.gitattributes` 要求 Python 文件使用 LF 但本地为 CRLF，git 一直将文件视为"已修改"，导致 `git checkout` 和 `git merge` 反复失败。

**根因**：
- `.gitattributes`：`* text=auto` + `*.py text eol=lf`
- Windows 上 `core.autocrlf=true` 导致检出时自动转为 CRLF，与 `.gitattributes` 冲突
- `git stash` 后 CRLF filter 立即重新修改文件，使 stash 失效

**修复**：
- 上传脚本 `_merge_work_into_release()`：`checkout` 到 main 后先执行 `git add --renormalize` + `git checkout -- .` 归一化换行符
- 全局关闭 `core.autocrlf=false`

**涉及文件**：`scripts/tools/github_upload_module.py`

## CI 镜像源切换导致 GitHub CI 全挂（2026-07-23，已修复）

**问题**：在 CI 配置中添加 `sed` 命令将 `archive.ubuntu.com` 替换为 `us.archive.ubuntu.com`，导致 GitHub CI 全部失败。

**根因**：
- `us.archive.ubuntu.com` 解析到 IPv6 地址（`2620:2d:4002:1::103`）且超时
- GitHub runner 使用 `archive.ubuntu.com`（全球 CDN），本来就不会出 502
- 本地 act 的 502 是代理/网络临时问题，不是 Ubuntu 镜像问题

**教训**：不要在 CI 中切换 Ubuntu 镜像源。`archive.ubuntu.com` 是全球 CDN，GitHub runner 上不会出问题。

**修复**：回退 sed 命令，恢复原始 `sudo apt-get update`。

**涉及文件**：`ci.yml`、`framework-ci.yml`

**状态**：✅ 已修复（v3.29.12）

## 子图 user_input 参数未提升为顶层变量（2026-06-29）

**问题**：图编辑器中复合节点（子图）内的 `user_input` 节点编译后只存在于子图 `parameters` 中，不生成顶层 `variables`。导致布局编辑器变量列表为空，ComputeSheet 无法渲染输入控件。

**根因**：编译器（`compiler.py`）和适配器加载器（`adapter.py`）只处理顶层 `variables`，未遍历子图 `parameters`。而 `user_input` 节点在子图内，其信息被困在 `subgraph.parameters` 中。

**修复**：
- `compiler.py`：编译复合节点时，检查 `dag_n.bindings`，只提升未连线的 `user_input` 参数
- `adapter.py`：`_promote_subgraph_user_inputs()` 递归收集所有 CallNode 绑定，只提升 `bindings[param_id] == ""` 的参数
- 变量路径格式：`子图名.节点标签`（如 `模拟计算.输入1`）

**关键约束**：只有未连线的 `user_input` 才提升——已连线的参数由上游节点提供值，不需要用户输入。

**涉及文件**：`framework/src/calc_framework/graph_editor/compiler.py`、`framework/src/calc_framework/config/adapter.py`
